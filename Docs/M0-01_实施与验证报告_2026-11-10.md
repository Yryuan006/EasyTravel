## 正式结构与职责

```text
easytravel/backend/
  __init__.py
  main.py                      # composition root：应用工厂，装配路由和异常处理
  config.py                    # 显式环境配置，启动时校验
  api/
    __init__.py
    errors.py                  # HTTP 错误契约及异常映射
    v1/
      __init__.py
      router.py                # /api/v1 路由及存活响应
  application/__init__.py      # 后续用例协调、身份/事务边界、端口的预留位置
  domain/
    __init__.py
    errors.py                  # 不依赖 HTTP 的业务异常
  infrastructure/__init__.py   # 后续数据库、模型、外部工具适配器的预留位置
tests/backend/test_app.py      # 独立 HTTP 基础测试
scripts/verify_backend_http.py # 临时启动真实服务器、采集 HTTP 和 OpenAPI
```

正式包独立于实验包，避免根目录 `application.py` 命名冲突。Application/Infrastructure 本轮仅定义包职责，没有虚构旅行用例或增加空泛 Repository 框架。未来 HTTP 路由调用 Application；Application 协调 Domain 及端口；Infrastructure 实现端口，由 main 装配。不得让领域规则依赖 FastAPI、数据库或模型，不直接发布实验 Repository、demo 身份和旧图。

## 本地启动与实际响应

在仓库根目录 PowerShell 执行：

```powershell
$env:UV_CACHE_DIR = Join-Path $PWD '.cache/uv'
$env:UV_PYTHON_INSTALL_DIR = Join-Path $PWD '.tools/python'
.tools/uv/uv.exe sync --frozen
$env:EASYTRAVEL_APP_ENVIRONMENT = 'local'
.tools/uv/uv.exe run --frozen --no-sync python -m uvicorn easytravel.backend.main:create_app --factory --host 127.0.0.1 --port 8000
```

正式入口是 `create_app()`，没有全局应用实例，没有导入时读取配置、数据库初始化或模型调用。代码创建应用时也不访问数据库、LLM 或预订接口。测试可注入 `Settings(environment="test")`，多次创建应用不共享可变全局配置。

真实 Uvicorn 运行结果（完整原始输出见 `M0-01_HTTP运行证据_2026-11-10.txt`）：

{"status":"alive","scope":"http_application_liveness","dependencies":{"database":"not_checked","model":"not_checked","travel_data":"not_checked"}}

这仅表示 HTTP 应用能响应，不能用于判断数据库、模型、旅游数据可用或业务就绪。本轮没有 readiness 接口。`/openapi.json` 和 `/docs` 实际返回 200。生成文档版本为 OpenAPI 3.1.0，使用 FastAPI 的 OpenAPI Pydantic 模型校验，快照见 `M0-01_openapi.json`。正式业务路径仅 `/api/v1/health`；异常测试用路由只在测试工厂实例上临时注册。

## 配置与安全错误边界

- 复用 Pydantic 和标准库，无新增配置框架。仅支持 `EASYTRAVEL_APP_ENVIRONMENT=local|test`，必须显式提供。缺失、空值、production 等不支持环境及未知 `EASYTRAVEL_APP_*` 配置均使启动明确失败，诊断包含字段名，不包含输入值。
- Settings 严格校验、冻结、禁止额外字段，Pydantic 文本异常隐藏输入。`debug=False` 固定，不支持通过环境启用调试堆栈。
- 正式应用不自动读取 `.env`，不读取实验数据库 URL，不包含数据库密码或模型 Key；`.env.example` 保留原 ENV-00 示例并补正式环境说明。生产配置及连接生命周期需后续独立设计。
- Domain 的 `ResourceNotFound` 映射 404 / `resource_not_found`，`BusinessConflict` 映射 409 / `business_conflict`；未知 BusinessError 和普通异常回退 500 / `internal_error`。这是后续用例可使用的基础契约，本轮未实现具体旅游业务。
- 响应统一为 `{"error":{"code":"...","message":"..."}}`，只使用服务端固定文案，不回显 `str(exc)`、数据库 DSN、任意 HTTPException detail/headers、请求原文、Pydantic 输入及 validator 堆栈。请求校验失败返回 422 / `invalid_request`，框架 HTTP 错误为对应状态 / `http_error`。
- 相关反例用含密码和 API Key 的合成 DSN 验证。基础错误处理尚未加入日志平台、监控或正式认证；后续增加适配器时仍须控制日志脱敏，不能把异常原文直接写入外部日志。

异常处理采用 FastAPI 官方异常处理扩展点：[Handling Errors](https://fastapi.tiangolo.com/tutorial/handling-errors/)。
