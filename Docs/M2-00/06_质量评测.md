# 旅行规划质量评测方案

状态：评测设计，不是已执行的质量报告。本轮不接真实数据、不实现评测执行器；`evaluation-cases.json` 是可复现的**场景与夹具配方清单**，不是当前 PlanDraftOutput 的合法实例。后续实施需按此配方物化完整 V2 输入/事实、费用、预期输出，并冻结哈希；不得删掉失败案例或仅靠 JSON Schema/测试数量验收。

## 数据集与重复执行方式

基础集 ET-M2-v1 固定 12 个案例，包含用户要求的 10 类场景以及接口/模型越权和时间边界。全部使用虚构资源、合成价格和确定性事实，自写而非复制供应商数据。文中北京/杭州仅作用户需求语义，坐标和实体使用测试命名空间；不推荐为真实旅行。Mock 价永不成为真实 VERIFIED。为了测试 live 验证分支可在**隔离规则测试内**注入服务端受信的虚构来源对象，环境注明 synthetic，不允许通过生产 V2 门控；该分支断言与真实有效价格质量分开报告。

配方默认：1–2 成人、CNY/+08:00、公共交通优先；每天 09:00–11:00 主活动、13:00–15:00 次活动，15:00 后为可选/休息；1 天无酒店，3/5 天分别 2/4 晚，一个酒店；到店事件首日16:00，退房末日08:00，酒店政策入住15:00/退房11:00。相邻活动间已含步行/候车/换乘总时长30分钟，额外缓冲10分钟；入住/退房接驳同样建立 leg。营业08:00–18:00、停止入场17:00，例外为空且明确覆盖适用日期；所有关键事实均有服务器合成依据，事实有效期和时钟固定。往返到达目的地07:30/离开目的地18:30，接驳60分钟并有官方政策的合成记录；不能把这些时刻说成真实班次。

费用配方按 case 的 known_total 分配：酒店每晚20000分，活动门票每人每天2000分，餐饮每人每天6000分，市内交通每人每天2000分，往返城际及接驳每人30000分；差额（若有）为明确列示的必要杂费，不得负数。常规两人3天合计200000分（酒店40000+门票12000+餐饮36000+市内12000+城际及接驳60000+杂费40000）；两人5天300000分（80000+20000+60000+20000+60000+60000）；单人1天45000分（0+2000+6000+2000+30000+5000）。各字段 amount_basis/包含项固定，预算上限见清单；估算/未知单独指出。配方物化时确认每笔是否已含，不能临时改算式迎合预期。

执行步骤：

1. 固定基线 commit、合约/规则/fixture 版本、时钟、来源模式和 adapter 版本；默认断网、无真实密钥。展开配方并保存规范 JSON 与 SHA-256；前置不成立即报夹具错误，不计规划通过。
2. 对同一事实输入运行纯确定性检查，核对逐检查状态、费用小计/未知/约束、证据精确匹配、风险/确认门槛。每例运行生成、预览、确认、重放；改日期/人数的例子还覆盖重规划，历史快照只读比对哈希。
3. Mock planner 用固定响应验证集成；未来模型阶段固定模型/提示词/采样配置，每例跑3次，记录供应商 run ID和版本。尽可能固定种子但不假设远端完全可复现；所有重复的硬失败单独计数，不能取最好的一次。
4. 两名人工评审独立阅读行程与证据，禁止先看系统总结。分歧由第三方/架构 Review 裁决并保留依据。无真实旅行经验者不得单独给“可行性已证实”结论；小样本邀请熟悉试点城市的评审人核对体验。
5. 单独的获权真实小样本集由人工对照目标日期官方原始事实，记录观察时间、页面定位/请求引用、允许留存范围。覆盖≥10个地点、≥20条有向交通边、至少1个营业例外；若接酒店则另加≥10个日期/人数/房型查询及过期样本。覆盖数字为试点进入门槛，不代表全国正确率。

## 评分与否决项

五维各0–4分：0=危险/关键错误；1=缺重要信息且难补救；2=部分可用、仍需大量手工修正；3=关键需求满足，少量明确不确定性；4=证据与体验完整且表达准确。权重：可行性30%、数据准确性25%、预算可靠性25%、风险披露10%、用户体验10%。分数按分项/4加权至100。

| 维度 | 人工及确定性评估内容 | 专项门槛 |
|---|---|---|
| 可行性 | 目标日期开门、入口/路线顺序、首末班/接驳、住宿、密度和休息 | 已知硬时间冲突漏拦=0；关键未知伪装通过=0 |
| 数据准确性 | 随机事实逐一对照允许的原始依据，身份/适用范围/观察时间；区分样本缺失与错误 | 任何虚构来源/错误核验为否决；支持率=有适用证据的事实数/作出事实断言数，关键断言100% |
| 预算可靠性 | 完整费用覆盖、整数分/人数/房晚、税费/包含项、不重复、旧价失配 | 所有预算预期精确匹配；未知作零、已知超支漏拦、过期价VERIFIED均否决 |
| 风险披露 | 未知/估算/冲突/过期与用户动作，确认与预订区别 | 关键风险召回率100%；用户接受不改变核验事实 |
| 用户体验 | 容易理解每天去哪/如何走/花费范围、信息优先级、来源可达、失败恢复 | 两人评审均≥3；试点用户能回答“总额是否已知、哪些未核验、是否已预订、下一步做什么”至少4/4正确 |

放行须全部确定性关键案例符合预期、0否决项；各正常案例各维≥3，总分≥80，模型3次重复均无硬失败。退化案例按“正确拒绝/披露/补救”评分，拒绝本身不扣体验分，不追求所有案例生成成功。报告同时给出覆盖率、错误类型、未知比例、拒绝比例、刷新成功率和耗时/调用成本，不靠平均分掩盖单个危险案例。

事实抽样不可只取有证据的字段，应从用户看到的所有实质断言抽样，并审查遗漏的必需费用。不得用另一模型作为唯一事实裁判；模型可辅助整理，人工与规则负责最终结论。供应商沙盒响应正确只证明解析，不证明真实旅游数据准确。

## 回归记录模板与退出

每次保存 commit、fixture_hash、query/evidence摘要、run/模型/提示词/规则版本、固定时钟、逐项期望/实际、差异、人工分数/理由、否决项、接口延迟/调用量、结论与评审人。源数据许可限制禁止保存的内容不进入集；改用自写合成数据。金标准变更单独版本及说明，不能随输出自动更新。

发现否决项立即停止该来源/能力进入正式规划，保留诊断，回退已验收 Mock 体验并持续明确标识；修复后只重跑受影响集和必要关联回归。后续真正改数据库/确认链路时再做有针对性的隔离集成回归；M2-00 不做无意义全库运行。
