# 真实旅游信息需求分析

范围：中国大陆境内 1–5 天，1–2 名成人，单人或情侣，公共交通优先，人民币，Asia/Shanghai。港澳台、儿童优惠、无障碍保障、跨境与租车暂不纳入最小真实核验能力；收到此类关键条件先澄清或说明不支持。产品不收集证件，不预订、不支付、不保证可入园或有房。

“必须”指安排具体行程或给出核验结论所必需，不要求所有字段缺失都拒绝返回任何草稿。系统可返回部分候选及问题；不得以警告包装已知不可执行的方案。每个字段携带独立来源，地点身份可信不代表营业或价格也可信。

| 信息 | 最小字段及必要程度 | 缺失或冲突处理 |
|---|---|---|
| 目的地/景点身份 | 必须：城市/区县、稳定资源映射、名称、地址、类别；简介/推荐理由可选 | 同名异地、多入口不明先请求选择，不能按首个搜索结果锁定。无身份只能输出候选，不能安排为已核验活动 |
| 景点营业/关闭 | 定时活动必须：适用日期、分段营业窗口、停止入场、休息日/节假日例外、局部关闭、预约条件；建议游览时长可估算 | 明确关闭则移除或替换；重要必去点信息冲突未消解则阻断该候选，问用户是否换点；普通可替代点缺失可降为待核查候选，保留自由时间 |
| 门票 | 为完整预算必需：成人/优惠资格、人数、日期/场次、票种/联票、必选附加费、预约与余量状态 | 挂牌票价不是可售库存。缺价 null；有官方基础价但税费/附加馆不明则拆成基础价和未知项。资格不明不默认优惠 |
| 市内公共交通 | 跨地点段必须：出入口坐标、模式、出发/到达时刻适用性、步行/候车/换乘/乘车时长、首末班或时间覆盖、费用 | 查无结果不是交通不存在；无数据则 UNKNOWN。普通段可给出未核验建议并披露；依赖末班/远郊唯一接驳的关键段未知则不允许确认完整路线，改方案或询问用户 |
| 酒店位置/条件 | 多日住宿建议必须：可定位实体、入住/退房日期与时间政策、房型、房数、入住人数上限；设施对用户关键限制为必须，其他可选 | 位置未知不能宣称通勤可行；未证实设施不作保证。最小阶段可给出住宿区域建议，不能冒充现有 PlanItem.hotel 的具体可售酒店 |
| 酒店价格/可用性 | 精确预算必须：每晚或整段口径、含税费/到店付、早餐、取消政策、入住人数、库存观察时间、价格有效期 | 无库存或报价过期不能展示“可订”；不清楚总价则 unknown，可另列历史价作参考，不沿用为当前 quote |
| 城际交通 | 来回及中途跨城必须覆盖：实际车站/机场/港口身份、服务日期、班次、席别、票价/人数、检票及接驳缓冲、是否已开售 | 未到开售期只做时刻参考/估算，不能承诺票价与座位。无可信班次且当天往返依赖该段则阻断完整可行性确认；不使用网页内部查询端点 |
| 餐饮/其他费用 | 每日必须覆盖餐饮、饮水及必要交通/服务费；特定餐厅和菜单可选 | 可用明确假设的人均估算，乘人数与天数一次；未获依据填 unknown，不能漏项或填 0。押金单列资金占用，不等同消费；可选购物不冒充必要费用 |
| 地理/顺序 | 每个关键资源、入口/出口/站点、坐标系、跨地点有向边、出行模式与日期为路线判断必须 | 坐标系或入口不明则停止距离/路线比较；直线距离只用于异常筛查，不能代替公交可行性 |

## 约束与预算完整性

冻结的 RequirementsInput 已有出发地、人数、偏好、限制和日期；现有 TripRequirements 只含目的地、日期、币种与硬上限。未来服务端必须绑定冻结输入摘要，不能仅凭 TripRequirements 声称满足人数和重要限制。自由文本“不能爬楼”“只坐地铁”等先转为用户可审阅的结构化硬条件；未澄清的关键限制不由模型擅自猜测。

费用覆盖清单按每个旅客、每一天和每个住宿夜生成：往返城际/机场接驳、当地交通、酒店、门票及必选附加、餐饮、必要杂费。允许无住宿的 1 日计划；5 天通常 4 晚，跨夜出行另问，不自动推断。已包括早餐/公交票的套餐避免重复计算；每项标记 included_in 或独立费用，不以零金额隐藏未覆盖项目。真实免费必须有适用资格和有效依据；没有消费也不等于未知项免费。

## 输出与交互

行程页显示“资料核查至何时、适用于何日、人数/房晚、哪些是估算、哪些仍未知”；地点卡和相邻交通段分别有来源入口。预算分别显示已知小计、其中估算部分、未知项目数与原因；有未知项时不显示确定总额或“预算充足”。估算区间可作辅助信息，不改变硬上限规则。

返回四类动作：硬输入缺失→请求澄清；明确不可行→拒绝该候选并提供可行替换；关键外部事实未知→部分草稿、阻止完整确认并说明补证路径；非关键未知→警告和明确接受。公开数据查询无结果、服务超时、来源相互冲突使用不同提示。整体确认保留“规划确认、未预订、出行就绪未评估”的现有语义。
