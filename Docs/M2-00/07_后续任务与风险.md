# M2 后续任务拆分与风险清单

以下编号全部为**待 Review 候选**，没有授权自动执行。与旧里程碑的映射见 README。每个切片必须单独确认数据范围、来源许可、接口版本、验收证据及退出策略；完成一项不自动批准下一项，不把“可调用接口”当作完整旅行质量验收。

## 候选任务

### M2-01 最小真实地点与景点资料查询

前置：M2-00 架构 Review；冻结一个城市/10个地点样本；获取运营者 Key 与具体产品许可；书面确认事实持久化、署名、模型输入及夹具权利。接口：PlaceSource、ResourceRef/CRS、SourceResult 与 EvidenceV2 最小非价格子集；只读查询、消歧、可追踪引用。数据源：高德或百度择一，官方景点事实由获权人工摘要补足。

验收：10个地点身份/区县/入口人工比对100%正确或明确返回歧义，不得悄悄选错；配额/超时/错误和缺字段有合成夹具；生产来源与合成来源隔离；持久化只含获权字段。不引入报价/库存或公交已核验结论。退出：许可、范围或资源身份不成立时关闭 live flag，返回未核查候选，保留已验收 Mock。

### M2-02 地理顺序 营业与活动时间检查

前置：M2-01 资源/CRS已验收；冻结 OpeningFacts、F01/F02/F03/F05/F06 检查契约；官方营业/例外摘要保留权明确。接口：OpeningSource、Leg/酒店到离店事件、ValidationReport；尚无真实交通数据时 F03 时长只能UNKNOWN，不能拿直线速度当证明。数据源：同一地图地点事实 + 经营主体官方适用日期摘要，路线时长先合成。

验收：营业分段、停止入场、关闭冲突、跨日、酒店入住/退房、坐标系不匹配、主要活动密度有明确预期；F02已知关闭/时间冲突必须拦截。Q06及关联变体通过，人工审阅可解释。退出：无法解释/缺营业依据时仅出待核查活动；关键事实缺失阻断确认，不改写旧稿或历史快照。

### M2-03 基础公共交通路线核验

前置：M2-02；选定 API 实际支持的日期窗口、城市、首末班/缺字段语义与路线保存权限；实际账号调用额上限固定。接口：RouteSource、时刻适用性、F03/F04、有向出入口和分段时长。数据源：首个获权地图公交/步行 API，经营主体运营公告按许可补充；不顺带加入铁路内部接口。

验收：至少20条有向交通边人工对照，实际覆盖/时长偏差/未知比率报告；关键衔接漏拦0、无班次时不作保证；Q05及关键/普通段变体、末班边界/方向/换站/总时长包含关系通过。能力仅到“适用时段的合理衔接”，没有实时保证。退出：关键字段不足则标 UNKNOWN，移除该核验能力或限定城市/时段，不用模型补值。

### M2-04 价格证据与预算核验

前置：单独批准 PriceScopeV2、费用用途/覆盖迁移、所有评估入口与双哈希升级；价格来源具有长期快照保留权。**可先仅官方固定门票价，不要求酒店 API 一次到位**。接口：PriceSource、EvidenceVerifier、AssessmentContext、BudgetResult/确认披露V2；酒店库存如无来源独立未知。来源：景点经营主体官方费率；动态酒店另选获准合作 API/合同，再作为此任务子切片单独审批。

验收：Q04/Q07/Q08/Q09/Q10/Q12；人数/房晚/税费/包含项只算一次；金额/范围/过期/冲突/Mock全部负例；日期变化不沿用旧价；所有生成/修改/确认路径已知超预算拦截；历史快照不变；有针对性的隔离数据库集成检查。退出：口径/许可不足则 estimate 或 unknown，禁止通过构造旧 supplier_quote 提升 VERIFIED。

### M2-05 真实事实参与 Mock 或模型规划

前置：前述必要字段具备；来源模式、权限、数据送模型边界及运行总成本/时限固定；先Mock planner，真实模型接入本身仍需单独批准。接口：事务外收集/候选后补查/服务端绑定/ValidationReport，保持 ModelAdapter 权限边界；统一生成、重规划和修改的依赖失效链。数据源：只用已验收能力，不新增供应商。

验收：Q01/Q02/Q03/Q08/Q11端到端；网络期间无长数据库事务；输入变化/超时/Worker中断无半成稿；候选不可自带证据权威；确认时重算/过期409；旧快照及幂等回执不变。退出：失败保持原版本，显式降级为Mock/部分草稿并标识，不能悄悄混为真实规划。

### M2-06 旅游建议质量评估与试点结论

前置：冻结 ET-M2-v1，物化完整 fixture 和执行器；至少两名评审人及城市体验评审；获得真实对照样本许可；ModelAdapter 若为Mock则只给Mock集成质量结论。接口：评测运行输出、事实审计/人工评分表，不新增业务权限。数据源：自写合成集 + 单独隔离的获权真实对照集。

验收：执行 `06` 全部规则、逐场景报告和五维评分，0否决项；公开未知/拒绝和覆盖率，不将样本推广全国；可重放失败、记录固定时钟/fixture/规则/模型版本。退出：不达门槛则暂停真实能力放行，修复对应切片后复评；不靠调整金标准掩盖危险结果。

依赖顺序建议：01→02→03；04可在01与契约评审后独立推进但不自动授权；05依赖所声明能力对应的02/03/04；06的合成集物化可先开始，真实质量结论必须等05。以上均不要求并行 Agent 或新增调度系统。

## 风险与待确认登记

| 风险 | 影响/证据 | 责任角色与下一动作 | 进入门槛/退出策略 |
|---|---|---|---|
| R01 缓存/衍生事实/永久快照无许可 | 地图条款含限制，现有append-only快照无法事后补救 | 项目负责人/商务取得书面范围与版本 | 许可未清楚，不允许来源进入持久化确认路径 |
| R02 条款/价格变动 | 页面可能改版，公开单价非总成本 | 商务按上线日期重核，留记录 | 设置账户预算/限流；不能承受即关闭来源 |
| R03 官方页面陈旧/局部关闭 | 已见旧页残留和日期公告，官方不等于当前适用 | 数据核查人按实体/日期/范围复核 | 冲突不消解不通过关键检查；保留全部依据 |
| R04 未来公交支持不足 | 日期参数不保证真实目标日准确，部分产品不支持未来规划 | 技术负责人做城市/日期样本检查 | 限定能力范围；关键接驳UNKNOWN阻断 |
| R05 价格口径失配 | 旧PriceQuery无人数/税费/入住分配 | 领域负责人Review V2 与聚合算式 | scope精确匹配与负例通过前不启用真实quote |
| R06 成本遗漏/低价诱导 | 只列票/酒店会漏餐饮、接驳、必选费 | 产品/领域负责人审阅费用覆盖表 | 缺项实体化unknown；已知超支硬拦截 |
| R07 模型越权/供应商文本注入 | 原始响应可能含指令或虚构核验措辞 | 技术负责人限制输入/模型DTO | 规范化事实白名单；证据绑定只在服务端 |
| R08 提交时过期/外查期间改需求 | TOCTOU、外查占长事务 | 应用负责人Review版本与时间策略 | 短事务CAS/双哈希/边界测试；冲突失败无覆盖 |
| R09 历史快照与来源退出冲突 | 长期保留权与删除要求矛盾 | 商务/架构负责人先决定数据边界 | 不带长期权利的数据不进不可变事实；不声称哈希规避授权 |
| R10 fixture污染或“沙盒=真实” | 录制夹具可泄Key/PII或过期；测试响应是stub | 测试负责人保留许可与环境清单 | CI断网；replay不进入当前核验；合成数据作为默认 |
| R11 样本有限/体验质量低 | 算术正确也可能密集、绕路、无餐休 | 产品/城市评审人做独立评分 | 五维≥3/总分≥80且0否决；不达标停止放行 |
| R12 原M2与新编号误读 | 旧“深入规划”与本次范围不同 | 架构Review冻结编号映射 | 保留原文，仅候选编号；不自动启动后续 |

未确认问题：地图是否允许永久保存规范化路线与坐标、是否允许向选定模型传递；酒店准入费/覆盖/税费/复核接口/限流；地方目录实际可授权数据集；城际交通合法可用的API及成本；景点自动采集与内容使用权；真实场景目标质量和试点城市最终选择。任何一项都不以猜测作为已解决。
