# 路线及时间可行性校验设计

报告按检查项输出 `PASS / FAIL / UNKNOWN / NOT_APPLICABLE`，附 check_id、item_ids/leg_ids、evidence_ids、target_scope、rule_version、evaluated_at、valid_until、severity、action、reason_code。PASS 仅表示明确范围内通过，不命名整体 READY；模型和适配器无权返回系统 PASS。任何依赖输入 UNKNOWN 不得被聚合为 PASS；同一检查 FAIL 优先。已知不可行的候选不得生效或整体确认，仍可作为失败诊断供用户修改。

## 时间与地理模型

活动为带 +08:00 的半开时间区间；营业包括多个窗口、停止入场时刻、最短游览时长、预约场次、关闭例外。住宿“入住至退房的占用区间”与“需要到场的入住/退房事件”分开，不把酒店过夜视为与所有活动重叠。交通为有向 Leg：from_exit/to_entrance、起终坐标及 CRS、时间、模式、步行/候车/换乘/乘车分段、费用口径、可用时间范围。

同一景点南门进北门出、同名不同站、火车站换站、跨日到达必须显式建模。先消歧，再在单一坐标系中计算。GCJ-02/BD-09/WGS84 不可混用；转换由获授权工具完成并记版本，不能自行加固定偏移。直线距离仅检查“明显跨城/异常坐标”，不证明可步行或有公交。

## 检查矩阵

| 检查 | 确定性规则 | 需要外部核查的事实 | 缺失/失败决策 |
|---|---|---|---|
| F01 日期/结构 | 旅行日期内、时间正序、活动不重叠、每日覆盖、住宿夜覆盖，复用既有规则 | 无 | FAIL 为 blocker，拒绝候选 |
| F02 营业匹配 | 活动完整落在允许窗口内；入场≤停止入场；满足预约场次；关闭例外优先；分段休息不得跨越 | 日期适用营业/关闭/检票政策 | 已知关门 FAIL blocker；普通可替代活动未知→标待核查/改为空闲；重要必去活动未知/冲突→blocker，问替换意愿 |
| F03 跨点时间 | `next.start >= prev.end + leg.duration + extra_buffer`；duration 必含起终步行、候车/换乘，已包含的部分不重复加 | 时间适用的路径/时长、真实入口出口 | 不足 FAIL blocker；缺时长 UNKNOWN，不用直线距离/模型分钟数补成 PASS |
| F04 公交衔接 | 分段站点、方向、日期连贯；每段到站+换乘缓冲≤后段可用发车；末班及服务时间覆盖；首站发车不等于本站到站 | 目标时刻服务覆盖/首末班、换乘窗口、停运公告；线路方案不等于实时班次保证 | 明确无服务 FAIL；同城普通非关键段 UNKNOWN 可警告；末班、偏远唯一接驳、赶火车等关键段 UNKNOWN 为 blocker |
| F05 酒店到离店 | 到店事件不早于允许入住（或明确寄存/提前入住依据）；离店事件符合退房；入住夜覆盖；两人房型容量足够 | 酒店时间政策、容量/设施、可售库存（独立检查） | 时间冲突 FAIL blocker；时间政策缺失不能默认 14:00/12:00 已核验；关键限制缺证阻断具体酒店推荐确认 |
| F06 密度与休息 | 汇总每日活动/交通/步行/休息；工作日/首末日时段区别；不超用户硬限制 | 景点合理游览时长/路径，步行距离 | 硬限制超出 FAIL blocker；默认密度阈值触发 warning，允许明确接受但仍需有物理时间 |
| F07 人数/预算/限制 | 冻结输入一致、价格范围与人数/房晚一致、必要费用覆盖、已知费用不过硬上限、结构化重要限制满足 | 设施/准入/产品资格等事实 | 超预算必须 blocker；关键限制没有依据 UNKNOWN blocker；一般偏好未满足 warning并解释 |
| F08 证据时效 | 源身份、适用日期、effective_state、冲突、scope_digest 与当前方案相符 | 新数据收集、身份与公告人工核验 | 已过期不得 PASS；刷新或保留 UNKNOWN；模型不能清除问题 |

缓冲和密度是可审阅的内部建议值，不是运营商服务承诺：同城交通时长之外加 `max(10分钟, 交通时长×20%)` 的不确定性缓冲；服务商已含的固定候车/换乘不重复相加。铁路/机场接驳以站点官方提前检票/值机政策及实际进站步行优先；缺少关键政策时不给肯定接驳结论，不能用普通 10 分钟缓冲兜底。

初版密度建议：每日主要景点通常≤3个、活动加交通≤9小时、步行>8km 或连续活动>3小时无休息触发 warning；均为待用户试点评估阈值。用户明确的更严上限成为硬约束。模型可建议放慢/合并相邻点、预留餐休或说明体验取舍；不能依据偏好“浪漫”“不太累”自行宣布满足硬限制。

## 决策优先级与可理解披露

1. 不完整硬输入先澄清；不进入“已核验规划”。
2. 已知超预算、时间不够、明确关闭、硬限制违反：拒绝本候选/提案生效与确认；可生成不违反限制的替换，仍需规则检查。
3. 关键事实无法确定：返回部分草稿、blocker 和补证路径，不能靠用户接受风险将 UNKNOWN 改 PASS；用户可修改目的地/限制或提供待核查依据。
4. 非关键不确定性：warning，提供来源/时间/影响/用户动作，可明确接受后确认规划；价格仍未知，不代表免费或出行就绪。
5. 所有非不适用项均 PASS 才可输出“在所列证据与时间范围内未发现冲突”；继续显示库存/天气/临时运营变化等未覆盖项，不宣称整体路线担保。

“关键段”由确定性政策判断并持久化：连接城际出发/到达、末班附近、偏远唯一公共交通、影响用户硬限制/必去点、无合理替换的必需段。模型可提高风险级别，不能把关键段降级。普通景点未知若仍在正式活动列表，则整个路线检查为 UNKNOWN；即使允许规划确认，也不得显示路线全部通过。

示例：前活动 12:00 结束，路线总耗时 35 分钟，缓冲 10 分钟，下一活动 12:30 开始→FAIL；改为 13:00 可通过时间算术，但若路径仅支持当前时间、目标为下月，F04 仍 UNKNOWN。营业写“17:00 闭馆”而 16:00 停止入场，16:30 入场不得通过。库存未知不是开放时间 FAIL，两项分别记录。

## 模型与外部核验边界

模型仅产生候选、推荐理由、游览时长建议与替换建议；原始网页/供应商文本按数据处理，不作为指令。端口提供规范化事实，Domain 做算术和决策，人工核查人对经营主体公告/特殊例外负责。接口缺首末班字段就返回 UNKNOWN，不让模型从“常识”补齐；模型自写“路线已核验”“价格 VERIFIED”必须被丢弃或拒绝，并加入越权评测。
