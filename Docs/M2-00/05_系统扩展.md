# 现有系统的最小扩展方案

继续 FastAPI → Application → Domain，PostgreSQL 保存业务事实，现有单 Worker 执行外查和规划；ModelAdapter 仍只返回候选文本。无需多 Agent、RAG、Redis、Celery、连接池或分布式编排。以下均为待批准接口，不在本阶段创建客户端或迁移。

## 端口及规范化 DTO

在 `backend/application/ports.py` 或相邻小模块定义异步端口；供应商实现位于 infrastructure，Domain 不导入供应商 SDK、HTTP、FastAPI 或数据库。区分能力，不建立万能 supplier_json。

```text
PlaceSource.search(PlaceQuery) -> SourceResult[PlaceCandidate[]]
PlaceSource.detail(ResourceRef, ApplicableScope) -> SourceResult[PlaceFacts]
OpeningSource.lookup(ResourceRef, DateRange) -> SourceResult[OpeningFacts]
RouteSource.plan(RouteQuery) -> SourceResult[RouteCandidate[]]
PriceSource.quote(PriceScopeV2) -> SourceResult[PriceObservation]
EvidenceRepository.append/load_set(...) -> EvidenceSet
EvidenceVerifier.assess(facts, query, policy, now) -> EvidenceAssessment
FeasibilityPolicy.evaluate(plan, frozen_input, evidence_set, now) -> ValidationReport
```

| 输入/输出 | 最小契约 |
|---|---|
| QueryContext | run_id、冻结输入 hash、schema_version、deadline；provider 在服务端选定，不接受模型提供任意 URL/Key |
| PlaceQuery | 城市/行政区、关键字/类别、可选区域；数量上限；输出稳定 provider_ref、规范名称、地址、坐标+CRS、入口语义/歧义标记 |
| ApplicableScope | 日期/时段/时区；酒店住离店和人数等来自冻结输入 |
| RouteQuery | 起终资源/入口坐标+同一 CRS、城市、目标出发/到达时间、walk/public_transit、硬步行限制；输出有向段、分段时长/单位、运营时间适用性和缺失字段 |
| PriceObservation | 精确 scope、原始计价单位、整段金额/税费/包含项、库存观察状态、报价时刻与有效截止；不能输出 Domain 的 VERIFIED |
| SourceResult | outcome=ok/partial/not_found/unsupported/unavailable；facts[]、provider、environment、observed_at、source_reference、缺字段、授权策略 ID、结构化 error、是否可重试；即便 ok 也可能未核验 |

错误码至少包含 auth_denied、quota_exceeded、timeout、upstream_unavailable、schema_changed、unsupported_date、ambiguous_resource、permission_missing、no_result。HTTP 200 返回业务错误/空路线不等于成功；no_result 不推导闭馆/停运；schema_changed 不用宽松解析继续执行。返回事实和错误均不泄露原始请求或密钥。

外查限额为待批准默认：connect 2s、单请求总 5s、一次运行收集上限 30s、只读临时失败最多重试 1 次（0.5–1s 抖动，服从总 deadline/Retry-After）；auth/权限/模式错误不重试。单 Worker 本地 semaphore 和速率闸门按账户实际配额配置；设置每次运行最大地点/路线调用数和金额上限，额度不足时部分失败，不轮换 Key 绕限。供应商超时的 UNKNOWN 不被 Mock 静默补成真实数据。

## 生成与重规划的数据流

```text
短事务 A：接受/claim 既有 run；冻结 intake/base revision 和来源模式
    ↓ 事务结束
按需收集地点/营业/路线候选（有授权才允许 live）
    ↓
ModelAdapter 产生候选 ID/顺序/建议；只读取允许送模型的最小事实
    ↓
按实际候选收集缺失交通边/价格 → 服务端绑定证据 → 纯规则评估
    ↓
短事务 B：追加 EvidenceSet/评估结果，检查 run、owner、intake/base revision
        → 再以 now 校验新鲜度/预算/硬约束 → 原子附加工作稿或保存提案
```

沿用 `GenerationService.frozen_input/execute` 及 `GenerationWorker` 的事务外生成模式。网络在 UoW 外，短事务内只读取已保存事实和做纯规则计算；数据库可用时证据批次也可先单独短事务追加，再由最终事务引用。必须保证草稿和其证据集引用原子提交，不能草稿成功却证据不存在。外查期间输入变化则保存运行诊断并失败 stale_input，不覆盖当前工作稿；未附着证据标 orphan/run diagnostic，遵照保留策略处理。

REPLAN 不复用旧日期 quote；按 scope_digest 找出受影响价格/营业/路线和后续依赖边，重查或输出 UNKNOWN，重算所有费用覆盖与风险。酒店位置变更影响首末交通段，活动顺序变更影响相邻边。未变的静态地点证据只有仍新鲜且允许复用才复用。缺数据只允许一次受控替换/补查循环，不能无限递归花费调用量。现有 retry_of 与 Worker 中断恢复语义保留。

首次真实事实可与 Mock planner 共存：planner_mode 与 source_mode 是两个显式字段。例如 `planner=mock, source=live` 只说明候选顺序由 Mock 决定；真实地点证据可独立成立，Mock 合成费用仍 is_mock=true。不存在将整个行程一键标 real 的开关。live/sandbox/synthetic/replay 分层配置；CI 禁网且默认 synthetic，sandbox/replay 永不成为当下旅行报价的 VERIFIED。

## 领域迁移与预算全链路

采用显式 schema_version=2 的新 DTO 和适配层，不能将新字段直接塞入现有 extra=forbid 结构。先做端口/Evidence 合约与纯规则，后做 V2 持久化及 API；v1 原样读取且不升级核验结论。要求新增字段的历史事实若缺失，显示未评估，不能默认填人数1或 verified。

最小 V2 仍只安排活动和一个覆盖全程的酒店，不借此次设计扩成多酒店/跨夜多模式引擎。交通、餐饮和必要杂费新增稳定 `cost_purpose + scope + anchor`：活动门票锚定活动，酒店锚定酒店，跨点费用锚定 leg，餐饮锚定 day，往返交通锚定 trip。若首批暂用现有 item_id 结构，可通过**显式的 v1 投影**锚定当天活动，同时保存 V2 真实用途与 leg/day 关联；不得创建虚假景点或用标题解析费用用途。预算聚合只选 V2 费用清单一次，v1 投影不可重复相加。未批准该迁移前不接真实价格。

酒店“区域建议”另用 recommendation DTO，不能把区域伪造为具体 hotel resource。无真实酒店事实仍可保留清楚标识的 Mock 酒店草稿，但无法给出酒店位置/库存通过结论；这决定质量和确认报告中的 UNKNOWN/blocker。真实路线与价格能力分别逐批引入。

必须覆盖现有所有评估入口：根 `rules.evaluate_budget/assess_confirmation`、Domain `check_constraints/validate_initial`、Application plans/changes/replanning/generations/confirmations 的当前/候选/待需求预算、确认预览和 POST、风险摘要与历史展示。通过统一服务端 AssessmentContext（冻结输入、EvidenceSet、rule_version、now）传递，消除各处硬编码 `{}`，但 v1 Mock 模式仍传空集且永不 VERIFIED。不能只修改工作稿展示，让确认/修改路径继续用旧规则。

## PostgreSQL 持久化边界

追加迁移，不修改 001–007。拟议逻辑表：source_policies（许可/版本/保留与模型使用范围）、evidence_records（不可变规范事实/引用）、evidence_assessments（追加核验事件）、evidence_sets 与 set_members（按 run/草稿绑定）、validation_reports、draft_evidence_bindings、snapshot_assessment_disclosures。所有绑定带 owner/trip/revision，复合外键阻止跨旅行/所有者引用；仓储读取延续所有权过滤，源映射不暴露其他用户查询。

不把 Key、完整 URL 查询参数、登录态或原始 HTTP blob 存进 Domain/快照/日志。只存获权的规范化最小事实和可追踪脱敏引用；若协议仅允许短期缓存，则临时材料单独存并按 retain_until 清除，不进入 append-only 永久表。不能以“数据库不可变”为由违反删除条件；**没有长期保留权的规范事实也不能进入永久 evidence_records/快照**。许可门槛不通过则关闭该来源正式确认功能，不事后修改快照来补救。

观察记录、规则输出和确认时披露版本分开：历史快照永久保存当时预算/适用日期/证据状态/风险/评估版本（前提是有权留存）。供应商后续变化在新工作修订产生新证据，不更新历史 snapshot 或 source draft。历史来源链接可失效，显示“当时核查依据，非当前报价”，不从网页实时重算历史事实。hash 只证明内容一致性，不证明真实性或许可。

## 刷新与确认的并发设计

新增显式来源刷新用例（候选 `POST .../evidence-refreshes`，202，复用现有单 Worker/运行状态）；不在 GET/confirm 中直接打供应商。旧快照永不触发刷新。刷新产生新的证据集和评估，若改变费用/时间则形成新工作修订或修改提案，保留已有保护/具体授权规则。

确认 preview 和 POST 都读取同一类本地 EvidenceSet，按 `03` 的边界重新计算；EvidenceSet/current revision 在短事务里锁定或 CAS。确认开始前数据不够新则回 source_refresh_required；用户可在政策允许时审阅 UNKNOWN 并接受，但关键 blocker 仍拦截。新证据到账/过期、人数/日期变化导致哈希不一致均须重看。幂等回执重放返回原快照，不用最新价格重写已确认预算。

## 测试分层

合成端口 fixture 明示 fabricated、固定时钟、内部虚构 ID；录制 fixture 还需 provider/条款许可、采集日、脱敏证明、请求范围与响应哈希/版本，不是删 Key 就能自动入仓。replay 固定 observation 和测试评估时钟，只能证明适配器语义，不能成为当前用户规划的 live 证据。后续获得授权后，少量显式 opt-in 集成检查验证真实端点/配额/字段，不进入默认 CI，不预订、不发短信、不支付。
