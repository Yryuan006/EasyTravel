## 最小契约与输入边界

所有模型复用 `extra=forbid, frozen=True, strict=True, hide_input_in_errors=True`。集合为不可变 tuple；活动最多 30 个，事实最多 100 条，每个事实最多 7 个周常日和 31 个例外，每日最多 8 个窗口。重复活动 ID、事实 ID、周常日、日期例外均拒绝；这类非法输入是契约错误，不伪装成有效的 UNKNOWN 事实。

| 契约 | 关键语义 |
|---|---|
| `OpeningFacts` / `opening-facts-v1` | 内部资源引用、精确入口范围、含首尾的日期适用范围、Asia/Shanghai、合成来源、周常日、日期例外、例外覆盖是否完整 |
| `OpeningSource` | 固定 provider=`synthetic_opening_fixture`、environment=`synthetic`、state=`SYNTHETIC_UNVERIFIED`；source_id、合成引用、observed_at、expires_at；无 supplier 更新时间 |
| `OpeningWindow` / `DayOpening` | 当日正序半开窗口；closed 必须无窗口且无准入规则；开放必须至少一个窗口；窗口有序不重叠；相邻窗口可连续，正间隙不能跨越 |
| `OpeningException` | 目标日的整日替代规则；OVERRIDE 明确覆盖周常，UNRESOLVED 表示与周常尚未消解，不由模型选择权威 |
| `AdmissionRule` | `last_entry` 包含截止瞬间；显式 null 表示没有额外入场截止；最短游览分钟数及预约是否必需均必须给出；整个 admission 缺失则 UNKNOWN |
| `ActivityVisit` | item_id、名称、ResourceRef、可选 entrance_id、带时区开始/结束、重要性、合成预约条件；名称只展示，不能成为身份依据 |
| `FeasibilityCheck` | F02 子检查、四态结果、固定原因码、项目/内部资源/入口、目标时间、fact_ids、severity/action、规则版本 |
| `ValidationReport` / `opening-validation-report-v1` | 注入时钟 evaluated_at、规范输入 SHA-256、逐项结果、聚合状态、有效截止、固定评估范围、真实旅行/确认快照/整体 READY 均为 false |

外部文本只能进入长度受限的 note 或限制说明。note 从不参与结论；不支持的限制说明产生 UNKNOWN，不能被执行。外部输入添加 verified/status/evidence_id 等权威字段，或伪造 live/provider/VERIFIED 会被严格拒绝。Application 再次重建嵌套模型，拒绝通过 model_copy 绕过校验的篡改对象。

这些 DTO 不对模型或 HTTP 开放。合成夹具可以表达“例外已明确覆盖”的测试条件，但不具备核验现实营业信息的权限。即使构造合法营业时刻，也只能得到 synthetic F02 结果。完整真实 Evidence、核验人/政策及持久化仍未实现。

## F02 决策语义

1. visit 要求内部地点身份。free_time 必须无地点和入口，F02 返回 NOT_APPLICABLE；空输入也不能得到 PASS。空闲时段的结构合法性仍属于未实现的整体 F01。
2. visit 时间必须标 Asia/Shanghai，开始及结束的实际偏移均为 +08:00，结束严格晚于开始且同日。不符合→FAIL；本版不支持跨午夜，包括结束于次日 00:00。不默默转换时区或拆分跨日活动。
3. 仅检索同一 internal_resource_id。相同 ID 却 city/district/provider/provider_resource_id 不同→绑定冲突 FAIL；不同内部 ID 的同名点永不借用事实。入口必须精确相等；主体 None、南门、北门不可互换，缺匹配入口事实→UNKNOWN。跨供应商内部身份合并不在本阶段实现。
4. 事实要适用于活动当天；observed_at 不得在评估时钟之后，且 `observed_at <= evaluated_at < expires_at`。不适用、未来观察或过期→UNKNOWN，并保留对应 fact_id。观察日期不等于营业适用日期或供应商更新时间。
5. `exceptions_complete` 表示该事实适用范围内判断所需的日期例外是否已完整掌握，不代表来源已核验。当目标日期有适用 OVERRIDE 时，替换整个周常日，包括窗口和 AdmissionRule；不从周常偷偷继承未知准入规则，其他日期例外不完整不阻止该目标例外生效。目标日期有 UNRESOLVED 例外→UNKNOWN。没有目标日期例外且 `exceptions_complete=false`→UNKNOWN / exceptions_incomplete，保留 fact_id；不得据周常关闭、窗口、停止入场、最短时长或预约限制产生确定性结果。例外完整但没有该周常日且无目标例外→UNKNOWN。
6. 对多个可适用来源逐个提取日规则，不按观察时间、名称或排列选赢家。任一可适用的未消解例外或缺少目标日例外且资料不完整，均使本活动营业相关判断保持 UNKNOWN，不选择另一个来源覆盖不确定性；可确定的日规则不一致也为 UNKNOWN，原因 source_conflict。即使一个说开放、另一个说关闭，也不直接判已知关闭。已过期/不适用的来源不参与择胜，但其 UNKNOWN 仍保留，策略偏保守。
7. 在目标日规则可确定且无冲突的前提下，明确关闭→FAIL。开放活动必须完整处于同一个连续窗口；中间停业、早到或晚离→FAIL。结束等于闭馆可通过半开区间检查；开始等于停止入场可通过，晚一秒即 FAIL。例外完整性判断先于使用周常规则，不能先输出依赖未知前提的 FAIL 再追加 UNKNOWN。
8. 明确最短游览时长不满足→FAIL；预约必需但明确没有→FAIL，预约状态未知→UNKNOWN；其他未实现限制→UNKNOWN。未提供完整 AdmissionRule 不能推断“无截止/无最短时长/无需预约”。
9. 同一活动和跨活动均 `FAIL > UNKNOWN > PASS > NOT_APPLICABLE`。例如例外完整时午间闭馆已知冲突，同时准入信息缺失，报告仍 FAIL；独立的活动时间倒序或时区错误也仍为 FAIL。该优先级用于独立且前提充分的确定性检查，不会将来源之间尚未消解的矛盾或不完整例外误称已知关闭。

FAIL 是诊断 blocker，建议修改活动；普通 UNKNOWN 为 warning/补事实，重要活动 UNKNOWN 为 blocker/补事实或替换。这里只输出建议动作，不改变现有业务确认规则，不发送确认请求，也不能由“接受风险”将 UNKNOWN 升为 PASS。

只有 F02 全部适用子项通过才有 PASS。report.valid_until 仅在 PASS 时取用到的来源 expires_at 最小值，是合成观察在评估时刻的复用截止；不保证未来旅行日期一定开放。UNKNOWN/FAIL/NOT_APPLICABLE 的截止为 null。日期变化必须重新传入活动并评估，输入摘要相应变化；没有缓存或旧结论复用入口。

## 可追踪性与实例评阅

固定时钟 `2026-11-18T10:00:00+08:00`，虚构活动日期 `2026-12-07`。夹具资源“合成岚纸城/合成北区/合成檐星馆”不存在真实数据来源；没有供应商响应或真实坐标。

规范输入按活动 ID、事实 ID 排序，采用稳定 JSON 和 SHA-256；相同事实、时钟和规则重复输出相同报告。fact_ids 可回查同一完整输入中的合成来源、引用、观察时间和范围。文本内容变化可改变摘要，但不能控制结论。报告不是包含真实证据的 ConfirmedSnapshot。

[示例文件](ValidationReport示例.json) 保留每例完整输入和实际生成报告，检查以下用户可理解的行为，而不仅看 JSON 合法性：

| 场景 | 预期及解释 |
|---|---|
| S01 09:00–11:00 游览、08:00–18:00 营业 | PASS，但明确仅 synthetic F02，F03 公交和跨点交通未覆盖 |
| S02 11:00–14:00 游览，中间 12:00–13:00 闭馆 | FAIL，outside_opening_windows；用户需缩短或拆开活动 |

| S05 缺营业事实 | UNKNOWN，missing_opening_facts；不能用惯常营业补 PASS |
| S06 一个活动晚于停止入场，另一个缺资料 | 总体 F02 为 FAIL，同时保留另一个 UNKNOWN，不能只显示较轻警告 |

新增行为测试覆盖时间端点、午休、关闭/调整例外、Q06、跨来源冲突、未来/过期来源、日期变更、跨日/错时区、短游览、同名不同 ID、入口范围、行政区绑定、限制、来源伪造、文本指令、嵌套绕过、重复/限额、稳定输出、聚合优先级。

原有地点 59+71 项测试完整执行。原有 M1/后端 454 项通过已验收 `verify_m201a_isolated.py` 运行：每次新建容器/卷和 7 个空数据库，验证独立集群标识和非超级用户角色；ENV-00 仅只读指纹对照，未用其写测试。旧测试生成的证据复制到本阶段 `旧测试本轮证据/` 后，旧文件逐字节恢复。回归结束停止新集群并保留资源；ENV-00 恢复原先停止状态。

首次回归在容器刚启动、只读指纹连接前因尚未就绪退出，未运行测试写入；新包装器加入 pg_isready 门禁后重新执行。一次基线核查在回归尚未结束时检测到测试暂写旧证据并按设计拒绝；最终核查只在回归恢复旧文件后执行。这两次不是业务测试失败，不将中间结果计为验收通过。
