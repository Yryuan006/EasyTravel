## 实现与状态边界

- `TripWorkspace.vue` / `useRequirements.ts` 分离已保存 TripView、编辑输入、单条问题、未完成命令。编辑表单从当前 TripView 初始化；保存成功才替换服务端摘要。失败保留输入。
- `RequirementsForm.vue` 复用创建/编辑；支持地点、具体日期/范围、天数、人数、两类预算、交通/酒店、限制和原始文字。三态 `unanswered/provided/no_preference` 保持独立。原文不提取事实，元输入精确转换整数分。
- `ClarificationCard.vue` 只展示后端当前问题，绑定 question_id、field_key、intake_revision。文本/日期/1–5 天/1–2 人/元金额使用对应控件；无偏好按钮服从 allow_no_preference。问题原文可能提及整数分，控件旁明确说明按元输入、提交转换。
- 回答及更新均提交两个 expected revision；无工作稿时 expected_working_revision=null。成功后使用后端 TripView 并重新读取下一问题；无问题时不虚构问题。blocking_fields 与保存摘要来自后端。
- 必需硬预算无法给出金额时可暂停。必需项回答 no_preference 后仍阻塞则自动暂停，避免立即循环追问；继续补充由用户主动触发。不创建默认预算、不标记旅行失败、不丢失已保存事实。
- 保存记录完整路径、body、UUID key。超时、网络或响应契约异常等不确定结果支持人工原请求重试；内容变化用新键。409 command_in_progress 可原样重试，idempotency_key_reused 禁止原样重试，其他版本/旧问题冲突要求重新读取和审阅。
- 409 不覆盖本地表单；先读取最新服务端摘要，锁定旧输入，人工审阅后才能再次保存。旧回答只作核对展示，不自动填到新问题。进入编辑即清除旧问题与旧回答重试命令。
- identity reset、组件卸载与新建导航销毁前一身份的本地状态；AbortController + epoch 阻止迟到响应覆盖新页面。Token 仅在页面内存；不进入 URL、浏览器存储、证据日志或 VITE 构建变量。
- `working=null` 仅接受 NO_DRAFT；已有 WorkingDraft 仅接受 STALE，显示 revision 与只读风险说明。历史快照指针不代表当前稿确认。没有行程编辑、重规划或确认按钮。

## 实际 OpenAPI 与 TypeScript 对应

`M1-03b_openapi.json` 从实际 TCP `/openapi.json` 读取，验收脚本断言与已验收 M1-03a 完全相等。

| 操作 | 路径 / 状态 | TypeScript 与运行时边界 |
|---|---|---|
| createTrip | POST /api/v1/trips → 201 | CreateTripRequest / validTrip；保留 M1-02 路径 |
| getTrip | GET /api/v1/trips/{trip_id} → 200 | TripView / validTrip；校验请求与响应 Trip ID 一致 |
| updateRequirements | PUT /api/v1/trips/{trip_id}/requirements → 200 | UpdateRequirementsRequest；expected_intake_revision、expected_working_revision、requirements |
| getNextQuestion | GET /api/v1/trips/{trip_id}/clarifications/next → 200 | NextQuestionResponse / validNext；问题可 null，存在时校验 revision、字段、ID、prompt 和 allow_no_preference |
| answerQuestion | POST /api/v1/trips/{trip_id}/clarifications/{question_id}/answers → 200 | AnswerRequest；两个 expected revision、field_key、answer。字段与路径取自当前问题 |

写请求均使用新的有效 UUID Idempotency-Key；不确定结果原路径、原键、原 body 重试。路径 ID 按实际 ID schema 接受 1–80 位字母数字/下划线/连字符，幂等键仍为 UUID。

TripView 扩展 working、latest_confirmed_version_id 与 NO_DRAFT/STALE。`working-schema.json` 原样摘取 WorkingDraft、TripRequirements、PlanDraftOutput、PlanItem、CostLine、PriceQuery、ItemConfirmation，`working.ts` 对其 $ref、anyOf、类型、required、extra、常量、枚举、长度/范围及日期格式执行校验。测试逐项与实际 schema 比对。TypeScript 的工作稿 payload/requirements 作为只读不透明对象处理，不提供行程字段操作；领域语义校验仍由后端负责。
