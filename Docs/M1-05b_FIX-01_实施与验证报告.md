# M1-05b FIX-01：确认成功后的版本状态同步

基线：`b2259143293039f150d946929e4e821a19fc8922`。范围仅为前端状态、展示与测试；不启动 M1-06a。

## 修复

`useConfirmation.ts` 将当前确认成功改为根据最新 TripView 派生：Trip ID、顶层及工作稿快照指针、来源 working revision、intake revision、CURRENT 同步状态和 CONFIRMED 确认状态必须同时匹配已收到的快照。

区分“HTTP 201 后尚未成功读取核对”和“已经核对、现在属于历史的回执”。前者保留快照并锁定写入，仅允许继续读取核对；后者保留历史事实但不永久阻止未来有效工作稿重新预览、手动同意和确认。每次新的 HTTP 201 都重新进入待核对状态。身份切换仍清除页面内存，epoch 和修订检查仍阻止迟到响应恢复旧状态。

`ConfirmationReview.vue` 在新需求使当前稿 STALE/UNCONFIRMED 时显示“此前版本已确认，当前规划未确认”，保留真实快照 ID、来源工作稿、时间和预算。当前版本重新读取仍显示确认成功。版本变化继续清除勾选；未核对回执不会被误当历史回执解锁。
