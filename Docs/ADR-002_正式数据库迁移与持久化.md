# ADR-002：正式数据库迁移与持久化

日期：2026-11-10（Asia/Shanghai）。状态：M0-02 采用，待 Review。依据 ADR-001，基线为 `a0e5da3fb51b7e3717d03c6a7aa96cf0c3198005`。

## 决策与取舍

继续 PostgreSQL + psycopg3。采用仓库内顺序 SQL 文件、数据库迁移台账、SHA-256 校验和及事务级 advisory lock 的最小显式升级器。首个文件 `001_initial.sql` 创建正式业务结构；台账由升级器引导创建。已应用文件不可修改，新变更追加文件。启动、导入、HTTP health 均不执行迁移。迁移成功才报告成功，失败退出码为 1；事务内 DDL 与台账一起回滚。重复升级为空操作；未知历史、非已知前缀或校验和漂移明确失败。SQL 文件通过 `.gitattributes` 固定 LF，以免跨平台换行改变校验和。

本阶段只有单一 PostgreSQL 方言及一个迁移序列，不需要 ORM metadata、自动生成 DDL 或分支合并。Alembic 可以独立于 ORM 使用，但目前会额外引入依赖、env.py/配置、revision graph、异步连接桥接和升级规范的维护成本，不能减少本轮手写约束/触发器工作，故暂不采用。不为工具改写已验证规则。未来出现多分支 schema 演进、部署版本管理需求时另行 ADR；当前方案只支持向前升级，修复采用追加迁移，不提供 drop/downgrade/自动清理。

## 数据结构

正式库独立配置 `EASYTRAVEL_DATABASE_URL`，固定业务 schema 为 `easytravel`。禁止使用旧 `easytravel_env00_test` 及 PostgreSQL 系统库，拒绝隐式目标、service/options/hostaddr 覆盖。所有业务 SQL 使用完整 schema 名，连接 search_path 固定为 pg_catalog；没有 public/Spike fallback。运行时不会自动读取 `.env` 或旧测试 DSN。

| 表 | 事实与约束 |
|---|---|
| trips | Trip 身份、所有者和创建时间；所有者不固定为 demo 身份 |
| draft_versions | 每次工作修订的 requirements、payload、项目确认；复合主键及所有权外键；禁止 UPDATE/DELETE/TRUNCATE |
| working_drafts | 当前工作修订及最新确认快照的指针；复合外键保证同一 Trip/所有者；CAS 更新修订 |
| confirmed_snapshots | 不可变确认事实、披露哈希、预算、确认人及时间；引用不可变源修订以还原完整快照；同 Trip/源修订唯一；禁止 UPDATE/DELETE/TRUNCATE |
| change_proposals | 类型化修改输出、候选、等级、项目集合、候选摘要、基础修订；保存为不可变事实 |
| specific_authorizations | 显式授权绑定提案、Trip、所有者、候选哈希、基础修订和精确项目集合；复合 FK 保证绑定；只允许从未消费到单次消费 |
| operation_receipts | 全局唯一服务端操作 ID、请求摘要和结果；不可变；同 ID 不同请求或所有者拒绝 |
| schema_migrations | 文件名、校验和、应用时间，仅显式升级器维护 |

这不是复制 Spike 表结构：Trip 独立建模，工作内容按修订追加，快照引用不可变版本；授权范围与消费回执由关系约束连接。JSONB 保存既有复杂领域契约，关系列负责身份、修订、关联和唯一性；领域 Pydantic/规则负责内容完整性及预算/披露语义，数据库不会复制整套旅行规则。

## 分层和事务

正式 Domain 提取既有安全修改模型/纯规则，移除固定身份和实验 digest 依赖；继续复用根目录纯 `contracts.py`、`rules.py` 的已验证契约/预算/披露逻辑。这两个文件不依赖数据库、FastAPI 或实验；旧 Spike 包完全不改。Domain/Application 无 psycopg/FastAPI/LangGraph/实验包依赖。

Application 接受必须显式传入的可信 actor，经端口选择每个用例的 unit-of-work 范围。PostgreSQL 适配器实现连接、事务上下文及 Repository；Repository 不自行提交。每个用例独立连接，成功退出才提交，异常或提交失败向上传播，回滚并关闭连接；无连接池、全局共享连接或后台迁移。迁移使用同样的显式连接生命周期。

每个 Trip 在短事务内锁定；写入前重新构建候选和校验授权、预算、披露。工作修订通过 CAS 推进并追加版本。幂等写入先取得 operation_id 的数据库事务锁，读取持久化回执，再进行过期修订校验；重试返回原结果。授权消费、版本/指针更新、回执在同一事务内提交；消费到回执的 FK 延迟到提交时检查。快照和版本在数据库层不可变，整体确认不等于酒店授权、就绪或预订。

actor 是后续认证适配器注入的可信用户标识，本轮没有登录或从 HTTP 接受 actor 的入口。Repository 的读取和写入使用所有权过滤，跨所有者返回不存在；复合 FK 防止跨 Trip/所有者关联。它是应用访问边界，尚未实现数据库 RLS、生产迁移角色与运行角色分权；拥有表/超级用户权限的管理员仍可更改 DDL。禁止将本轮测试角色当成生产安全部署方案。

## 隔离、测试与运行

专用 ENV-00 容器内新增随机命名的 `easytravel_m002_test_<suffix>` 数据库与独立 NOSUPERUSER/NOCREATEDB/NOCREATEROLE 所有者，撤销 PUBLIC CONNECT。只操作标签为 env00 的容器；不访问其他容器。每次完整数据库测试需要一个新库；测试没有 DROP/TRUNCATE/重置，资源保留待人工管理。凭据写入新的 ignored `.local/*.env`，不覆盖既有文件、不打印密码。

旧库的 24 张实验业务/Checkpoint 表在正式测试前后以行数和全行哈希校验。正式库内只有 easytravel 表，外键仅引用正式 schema；没有复制、恢复或迁移旧 Checkpoint。原有回归继续在旧专用测试库运行，允许其正常追加测试数据，不改变恢复语义。

本轮只建立持久化用例，没有完整生成流程、修改 HTTP API、认证、前端、真实模型、预订或多 Worker 调度。数据库锁的针对性并发测试不代表多实例调度已验收。M0-02 交付后停止等待 Review。
