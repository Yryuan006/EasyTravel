## 2. 最小集成实现

新增 `easytravel/m000/`，未修改 Spike-01/02/03 源码、测试、图版本、依赖声明或锁文件。

```text
MockAdapter -> SafeChangeOutput -> PlanService.propose_change -> 领域规则
  L1/L2 -> PlanService.apply_working_change -> 新工作修订及回执
  L3    -> LangGraph interrupt（完整候选、摘要、基础修订、项目及说明）
             拒绝 -> 持久化拒绝决定 -> 结束
             批准 -> 原子保存决定及 SpecificAuthorization
                    -> PlanService.apply_working_change -> 新工作修订及回执
```

图版本 `m000-safe-change-v1`；独立 Checkpoint schema `m000_checkpoint_v1`、业务 schema `m000_business_v1`。业务表直接复用 Spike-03 的 DDL，额外 `integration_runs` 只绑定 thread/trip/proposal/operation 和决定。没有把实验结果表当成计划更新。

提案与运行绑定原子提交，崩溃后生成节点从数据库读取同一个提案，避免重新调用模型。首次授权必须来自匹配候选的动态审批中断；批准请求同时匹配提案、候选哈希、基础修订、项目集合和明确同意。图 resume 只引用已持久化 decision_id，不能自行创造授权。

决定和授权共用事务；修改沿用 PlanService 的授权消费、工作更新、回执同事务。提交后、图 Checkpoint 前崩溃时重新执行同一 operation_id，由已有回执返回原结果，不再次修改或消费授权。

## 3. 验证证据

`tests/m000/test_integration.py` 新增 **22 项**集成测试；真实 PostgreSQL Checkpoint 和业务事务，模型输入为 Mock。

| 验收点 | 运行证据和断言 |
|---|---|
| 类型化提案、L1/L2/L3 | 三条路径，Agent 各调用一次；L1/L2 直接应用，L3 真实 wait；修改修订 1→2 |
| 拒绝不修改计划 | 工作草案完整相等、旧快照完整相等、授权/修改回执均为零；冲突决定被拒绝 |
| 具体批准与安全修改 | 精确提案/hash/修订/项目/明确同意及身份门禁；批准后新工作修订，旧确认快照及其指针不变 |
| 审批不能提前或伪造 | 静态 wait 前批准/拒绝均失败；伪造 Command 不产生授权，错误 Checkpoint 需 Review |
| 领域约束继续生效 | 授权不能越过硬预算或过期修订；失败不修改草案/快照、不消费授权 |
| 决定事务回滚 | 插入授权后注入异常，决定和授权一起回滚；原请求恢复后成功 |
| 提案/决定/业务提交后退出 | 三个故障窗口均由子进程 `os._exit(75)` 强制退出；新 PID 恢复，再由另外进程重试 |
| 幂等及单次授权消费 | 恢复后恰好 1 提案、1 授权、1 修改回执、修订只加 1；授权 consumed_by 指向稳定 operation_id；恢复适配器调用为 0 |
| 拒绝决定提交后退出 | 新进程恢复为 rejected；草案/快照不变，无授权或修改回执 |
| 旧图隔离 | 旧 Spike-02 与新图使用同一 thread_id；新图完成后旧 CheckpointTuple 和 inspect 结果完全不变，旧图仍能正常拒绝恢复 |
| 无效模型输出 | 两次校验失败，不保存提案，不修改草案或快照 |
