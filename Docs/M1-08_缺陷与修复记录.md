## D01：STALE 确认预览的恢复指引仍称不支持重规划

- **严重程度**：P2，功能能力描述过时。用户可能误以为无法继续；既有同屏 REPLAN 入口仍可用，服务端安全拦截未失效。
- **复现步骤**：已有工作稿后保存新需求，使其为 STALE；打开“重新读取确认预览”。预览正确阻止确认，但 stale_intake 文案仍为“本阶段尚不支持重规划”。
- **模块与根因**：frontend/src/api/confirmations.ts 的 blockingText.stale_intake 沿用了重规划 v2 交付前的阶段描述。
- **最小修复**：只将该句改为“需求与工作稿不同步。请先审阅新需求并完成重规划，再读取当前行程的预算与风险；不能确认旧稿。”未改确认条件、授权、预算、模型、API、事务或数据库。
- **回归增强**：在既有“keeps 200 blocked preview non-actionable: stale_intake”测试中增加正确恢复指引和无过时描述的断言；保留禁用同意及不能提交的断言。完整生命周期还真实点击 STALE 预览，核对提示、不可确认，以及同屏重规划按钮可用，然后实际完成 v2 审批。
- **修复前结果**：`M1-08_D01_Vitest_RED.txt` 中相应分支失败，展示了过时文本。
- **修复后结果**：`M1-08_D01_Vitest_GREEN.txt` 的 3 个阻塞分支通过；全量 151 项 Vitest 和 61 项 Playwright 通过。最终生命周期针对性也通过。

针对性命令：在 frontend 下运行 `node node_modules/vitest/vitest.mjs run tests/confirmations.test.ts -t "keeps 200 blocked preview non-actionable"`。筛选外的 31 项未运行，不作为该针对性结果的通过项；它们在随后完整 151 项中执行通过。

## D02：默认 Node 低于工程声明的运行版本

- **严重程度**：P2，验收可重复性偏差，非业务缺陷。默认 Node 为 24.14.0，frontend/package.json 要求 >=24.22.2 <25；npm 为 11.9.0，符合要求。npm run 未因 engine-strict 自动拒绝旧 Node，因此初次检查虽通过，仍不能用作符合工具链约束的最终前端验收。
- **复现步骤**：执行 `node --version`，并与 package.json 的 engines 比较；再直接运行 npm run 的检查命令会继续执行。
- **根因与涉及模块**：M1-08 验证驱动最初依赖默认 PATH，未显式使用仓库已有的 .tools/node-m003/node_modules/node/bin/node.exe。
- **最小修复**：仅 M1-08 前端驱动显式采用仓库 Node 24.22.2，启动前断言版本，给子进程 PATH 优先放置同一 Node。Vite/Playwright 直接用该二进制启动；类型/构建/Vitest 由该二进制执行 npm 11.9.0。未安装依赖、修改 engines 或改变产品代码。
- **回归门禁**：驱动版本断言及 M1-08_前端工具链.json、M1-08_浏览器工具链.json；不匹配则中止，不允许静默降级。固定版本下重新执行完整 TypeScript、生产构建、151 项 Vitest 和 61 项 Playwright。Python 后端 454 项不依赖 Node，原结果保留。
- **前后结果**：原始默认 Node 日志以 `_默认Node` 后缀保留，不作为最终前端工具链合规证据。最终不带后缀日志对应固定版本；没有把第一次通过掩盖成一开始就满足版本要求。
