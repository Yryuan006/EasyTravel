## 交付行为

浏览器在 `/trips/new` 输入本地开发凭证，填写目的地或一句话需求，即可通过同源 Vite 代理 POST 到正式 FastAPI。只有 HTTP 201 且完整 TripView 校验通过才显示创建成功并更新地址为 `/trips/{trip_id}`。结果展示服务端需求、intake revision、收集状态、阻塞字段，以及尚无草案、未确认、未预订、就绪未评估的说明。

刷新或直接打开旅行 URL 时，页面没有 Token 或本地 Trip；重新输入凭证后 GET 正式 API，从 PostgreSQL 恢复。需求摘要只读，不提供更新、澄清或生成。原始文本不自动提取为结构化事实。

复用现有 App Shell、色彩、HealthStatus/useHealth、ApiError 和异步联合状态模式；仅扩展必要表单样式。采用原生 details 渐进展开日期/人数/预算及偏好，首屏仅呈现原始需求及地点状态。每个字段明确选择尚未回答、无偏好或提供内容。未填写为 unanswered/null；金额按人民币总额输入元，精确转换为整数分。

两个页面的当前需要由 History API、popstate 和 Vite SPA fallback 满足，不新增 Vue Router、Pinia、UI 框架或其他依赖。没有修改后端、既有迁移、锁文件或原后端测试。

## 源码与接口映射

| 正式 OpenAPI / 行为 | TypeScript / Vue 实现 |
|---|---|
| MissingAnswer / ProvidedAnswer：state + value | `src/api/contracts.ts` 的 Answer<T>，运行时检查状态与值对应关系 |
| FixedDates / DateWindow | TravelDates，严格 ISO date、实际日历有效性及起止顺序校验 |
| RequirementsInput.required | origin、destination、dates、days、travelers、target_budget_cents、hard_limit_cents、transport、hotel、restrictions、raw_text 全部出现；与归档 OpenAPI required 集合有测试比对 |
| 天数 1–5，人数 1–2，金额整数 0–10^12 分 | 数字在 TypeScript 表达为 number；人数为 1\|2；边界与整数约束由 validRequirements 及表单序列化运行时检查 |
| CreateTripRequest = {requirements} | `composables/requirements.ts` 只从明确表单字段生成请求，无 owner/actor/confirmed 等权威字段 |
| POST /api/v1/trips，201，Bearer，UUID header | `api/trips.ts` 的 createTrip；UUID 由浏览器 crypto.randomUUID 生成，发送 Authorization 与 Idempotency-Key；cache=no-store、credentials=omit |
| GET /api/v1/trips/{trip_id}，200 | getTrip，先验证 UUID，并检查响应 trip_id 等于请求 ID |
| TripView / IntakeView | TypeScript 对应所有字段；unknown 响应检查完整字段集、UUID、带时区 created_at、revision、全部输入、collection_status、blocking_fields、provenance、suggested_values |
| 本阶段无稿状态 | 严格要求 working/latest_confirmed_version_id/active_run_id 为 null，NO_DRAFT、UNCONFIRMED、NOT_ASSESSED、booked=false；非法状态拒绝展示 |
| ErrorResponse | 仅识别 status 与允许的业务 code，不回显服务端 message、原异常或原始响应 |

`validRequirements` 是前端格式防线，服务端仍为输入合法性和业务状态的最终权威。最小输入、未知字段拒绝由后端独立验证。日期/天数冲突、超过五天的具体日期区间、目标预算高于硬上限依 M1-01 作为阻塞字段返回；前端不将它们伪造成已经解决的事实。未实现通用 JSON Schema 生成器或完整语义等价证明。

模块：`RequirementsForm.vue` 输入；`TripSummary.vue` 只读摘要；`useTrip.ts` 读写状态、原请求保存、重试及过期响应保护；`App.vue` 本地凭证、页面地址和清除身份状态。健康组件与客户端未改变。

## 错误、幂等与身份

- 创建中禁用整个表单及提交按钮，重复 save 不另发请求。
- 401 提示缺失/无效凭证；403 提示本地环境不允许；404 统一不存在/无权；422 提示检查输入；503 提示业务依赖不可用。
- 409 command_in_progress 提示稍后手动同键重试；idempotency_key_reused 明确不同内容冲突并隐藏原样重试按钮；无自动换键或自动重试。
- 超时、断网、非法 JSON/响应结构、非预期成功状态均不宣称成功。原 key 和原始序列化 body 保留在页面内存，可明确点击原样重试。修改内容后提交使用新 key，并提示原请求可能已经创建另一旅行。
- 写请求超时或取消不代表服务端事务撤销。刷新后不保存待重试命令，不自动 POST；尚未取回的结果可无法从此 UI 找回，这是本阶段无旅行列表且不持久化待处理命令的限制。
- Token 只在当前页面内存；使用后清空输入缓冲，无 localStorage/sessionStorage/IndexedDB/URL/日志/VITE 变量存储。切换或清除凭证会卸载表单、清空结果和待重试命令，并通过请求世代比较抑制旧身份响应。
- 页面只有 DEV 且 loopback hostname 开放此入口。生产构建/preview 不开放本地凭证旅行功能；真正部署仍需后续正式认证，不将本方案用于公开部署。
