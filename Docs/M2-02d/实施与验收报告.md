## 数据契约与可信范围

沿用 strict/frozen/extra-forbid 的 PlaceContract；标识、人数、房间数和集合长度均有界。Application 重新验证完整嵌套输入，model_copy/model_construct 不能绕过 synthetic 限制。服务端内部 DTO 的 resolved_hotels 必须由可信解析层注入，模型/外部文本无权自报真实酒店身份或政策；本轮只使用完全虚构资源。

| 契约 | 语义 |
|---|---|
| HotelStay | 内部酒店完整 ResourceRef、房型、房间数、计划第一住宿夜日期和排他退房日期、到店/办理入住/退房三个独立事件、提前到店安排 |
| HotelPolicyFacts | 酒店与房型的精确绑定、日期适用范围、合成来源及 TTL、日期政策完整性、入住/退房/容量和惰性 note |
| CheckInPolicy | 最早/最晚办理时刻、明确的最晚日偏移 0/1、可选合成提前办理依据、寄存政策；无默认时间 |
| CheckOutPolicy | 明确截止时刻及可选合成延迟办理依据；无默认 12:00 |
| RoomCapacity | 房型标识和每间最大人数；null 表示未知，不表示无限容量 |
| LuggageStoragePolicy | ALLOWED/NOT_ALLOWED/UNKNOWN；允许时必须有明确同日时间窗口 |
| StayNightCoverage | 从计划日期区间确定性推导的每晚需求和 stay_ids，非外部事实；一晚只有一个住宿条目才通过 |
| F05FeasibilityCheck | 范围、酒店/房型/住宿标识、事实 ID、规则版本、事件/允许边界、容量及原因/状态/阻断/动作 |
| F05ValidationReport | 注入时钟、规范化输入哈希、逐项结果、派生夜覆盖、最短依赖 TTL；只评估 F05，库存及其他检查 NOT_EVALUATED，整体 READY/真实出行/确认快照恒 false |

HotelPolicyFacts 是带出处的事实聚合；其嵌套 CheckInPolicy、CheckOutPolicy、RoomCapacity、LuggageStoragePolicy 继承外层相同的酒店/房型、synthetic 来源、日期范围和时效，不是可以脱离外层授信的独立事实。来源固定 synthetic_hotel_fixture / synthetic / SYNTHETIC_UNVERIFIED，引用只能 synthetic-hotel:*；observed_at、expires_at 必须 aware 且过期时刻大于观测时刻。数据不能升级为 VERIFIED。

HotelStay 是计划输入，不是库存、真实预订或已支付凭证；“第一住宿夜/退房日期”描述计划房晚区间。StayNightCoverage 只说明计划住宿夜分配，不证明真实房间可售、已预留或整晚实际在房间。实际入住后的占用区间与到店/办理事件区分，不将跨夜占用当成与白天所有活动冲突，也不在本模块实现活动路线或 F01 规则。

## 日期、事件与取端规则

- 旅行起止日期为包含首末旅行日的闭合范围，要求 1～31 个旅行日。必需住宿夜为 `[trip_start_date, trip_end_date)`。一日旅行且没有住宿条目时为 NOT_APPLICABLE，不要求酒店政策，也不生成缺酒店错误。
- 每个住宿计划夜区间是 `[check_in_date, check_out_date)`，限定 1～30 晚。范围必须在旅行日期内。房间数只影响容量，不乘住宿夜数；多个住宿条目声明同一晚为重复覆盖 FAIL。连续两家酒店在退房日/下一入住日共享日期不重复计夜。
- 所有事件使用 +08:00，保留秒/微秒，不取整。要求 `arrival_at <= check_in_at < check_out_at`。到店/办理入住可以在第一住宿夜日期或紧接的次日，退房事件日期必须恰好为计划退房日期；其他日期不匹配 FAIL。
- 入住允许区间是 `[第一夜日期 + early_from或earliest, 第一夜日期+latest_day_offset+latest]`，包含两端。最晚日偏移仅允许整数 0 或 1；布尔值也拒绝。只有显式 offset=1 才支持次日午夜办理。普通当晚 23:00 截止不自动解释为允许次日 00:30；已知过晚 FAIL，最晚时刻未知 UNKNOWN。
- early_from=null 且日期政策完整，表示没有可采用的提前办理依据；早于已知 earliest 的办理事件 FAIL。early_from 有值必须早于正常最早时刻，属于本合成范围内的明确依据，不代表真实提前入住确认。
- 退房事件不晚于 `late_until或deadline` 则 PASS，相等允许，晚一秒 FAIL。late_until 必须晚于已知正常截止；它同样只表示合成政策依据。未知 deadline 且无依据时 UNKNOWN，不按酒店习惯填默认值。

未知最早、最晚边界分开保留；例如最早未知、最晚已知且明确超出，保留最早 UNKNOWN 与最晚 FAIL。各政策维度独立求值，已知退房失败不会因容量未知或入住政策来源冲突被抹去。

## 到店与寄存

到店时间不会直接作为办理入住时刻。早到但稍后正常入住时，不输出“提前办理入住”FAIL；提前到店安排必须明确：

- luggage_storage：只有明确允许且覆盖整个 `[arrival_at, check_in_at]` 的同日寄存窗口才 PASS。缺寄存政策或状态 UNKNOWN 时 UNKNOWN；明确禁止或窗口不覆盖为 FAIL。跨午夜寄存本轮 UNKNOWN / luggage_cross_day_unsupported，不把日间窗口外推为过夜寄存。
- offsite_wait：显式离店等待，不请求提前使用酒店客房/寄存服务，该到店子项 NOT_APPLICABLE；入住事件仍独立受政策约束。这不会宣称酒店允许提前入住或寄存。
- none：若早于已知允许办理时刻且没有上述安排，则 UNKNOWN / early_arrival_plan_unknown，不能默认可在酒店寄存或等待。已到允许办理时段且仅等待实际办理时，不产生额外提前服务需求。

到店与办理时刻相等，没有办理前寄存区间，寄存子项 NOT_APPLICABLE。即使寄存政策未知，只要没有寄存需求，也不凭空追加这一未知项。

## 完整性、来源与人数

酒店 ResourceRef（内部 ID、供应商 ID、城市/区）及房型必须精确匹配，其他酒店或其他房型事实不能借用。请求酒店不在可信注册表为 FAIL；匹配政策缺失为 UNKNOWN。

政策必须覆盖从第一住宿夜到退房日期的整个计划日期范围；范围不符、观测在未来或 `evaluated_at >= expires_at` 均 UNKNOWN。任一匹配候选过期/日期不适用/日期政策不完整时保守停止政策求值，不能从另一个来源择优恢复确定性结论。日期完整性表示相关例外均已掌握，不等于真实 VERIFIED；不完整时不能根据可能被例外覆盖的普通入住/退房/容量判定失败。

所有候选有效完整后，分别比较 check_in、check_out、capacity 维度，结构不一致的维度 UNKNOWN / source_conflict，不自动挑最有利来源；其他一致维度仍可独立判断。入住维度包含寄存和提前依据，冲突时整体保守未知。只有元数据、fact_id、note 不同而政策相同不构成政策冲突。

总容量=`room_count * max_guests_per_room`，已知容量不足 FAIL，等于或超过 party_size PASS，容量未知 UNKNOWN。不实现成人/儿童/加床等复杂资格分类，也不将政策允许人数等价为有空房。
