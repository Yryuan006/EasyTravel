# M1-00：前端页面与组件规划

日期：2026-11-11。低保真设计，等待 Review；没有新增 Vue 页面、依赖或视觉实现。

## 1. 页面与导航

使用任务型工作区：先提供信息，再看结构化结果、差异、风险并作决定。自然语言输入与结构化事实并排；聊天内容不作为唯一行程记录。复用当前 App.vue 的 header、skip-link、main、footer、styles.css 的基础视觉与响应式约定。保留服务状态入口，但不以 health alive 判断规划可用。

| 建议地址 | 页面职责 | 主要服务数据 |
|---|---|---|
| `/trips/new` | 轻量创建、自然语言及关键结构化字段 | RequirementsInput；POST trips |
| `/trips/:id` | 收集、澄清、生成状态、工作稿及最近确认摘要 | TripView、next-clarification、GenerationRun |
| `/trips/:id/proposals/:proposalId` | 可分享在同一本地身份下重新打开的提案详情 | ProposalView、decision |
| `/trips/:id/confirm` | 当前版本的预算及风险披露、整体确认 | ConfirmationPreview |
| `/trips/:id/history`、`/history/:snapshotId` | 不可变快照列表/详情，与工作稿区分 | SnapshotPage、SnapshotView |

这些是页面结构建议，当前未安装 Vue Router。M1-02 决定是否增加单一 Router（需批准依赖变动），或先用 URL+轻量页面切换；不能描述成已有路由能力。不增加 Pinia、组件库或新的样式体系作为前置。

[补充人数与预算 ▾] [偏好与限制 ▾]

创建按钮只承诺保存，不声称生成。字段有 label、单位、帮助文本、错误关联；键盘可操作，折叠区有 aria-expanded。明确“没有偏好”与“未回答”；隐藏可选字段不自动填默认事实。修改已填信息后不丢弃用户当前文字；版本冲突提供最新摘要和“重新审阅后保存”。

## 3. 工作稿低保真布局

```text
杭州 3 天 / 2 人    工作草案 r2（未确认）
最近确认 S1：源 r1  [查看]       [历史确认版本]
提示：模拟行程，价格及路线未核验；尚未预订。
若需求已变：需求 i4 与当前稿不一致 [查看变化] [重规划]
┌───────────────────────┬────────────────────┐
│ 第 1 / 2 / 3 天         │ 预算摘要            │
│ 09:00–10:00 活动        │ 已知小计 ¥…（含估算）│
│ 公共交通建议/待核验     │ 总额：暂无法确定     │
│ 成本：估算 ¥…          │ 硬上限 ¥…           │
│ 酒店/房型/入住退房      │ 未知 N 项 [明细]     │
│ [提出调整]             │ 风险与待确认 [展开]  │
├───────────────────────┴────────────────────┤
│ [第二天安排轻松一点……] [提交修改意图]        │
│ [查看预算与风险，确认当前 r2]                │
└────────────────────────────────────────────┘
```

每天按 +08:00 日期和 start 排序，跨日住宿显示入住/退房，酒店不与白天活动混成时间冲突。交通建议是建议，无核验站点时展示待核验；无法安排则显式风险，不伪造空白已完成。费用明细用表格：类别、所属项、总价、状态、来源/适用范围、未知原因；小屏改为保留列标题含义的列表。`null` 显示“未知”，0 显示“¥0（说明依据）”。

桌面主列行程、次列预算风险；小屏依次为版本状态→预算摘要→每日→风险→修改入口。确认按钮旁始终有版本标识；底部粘性按钮不能遮挡风险正文或焦点。历史页内容只读，禁止无提示替换当前草案。

```text
修改提案 P / 基于工作稿 r2 / L3 需明确授权
原因：换酒店；影响：酒店 H、接驳 A（逐个列出）
                修改前       修改后
酒店/日期/房型  ……           ……
接驳与时间      ……           ……（未核验）
费用/未知项     ……           ……
预算影响、保护状态及风险：……
[拒绝，保留当前稿]  [明确授权以上项目并应用到工作草案]
说明：仅本提案；不确认整份行程；不发生预订。

确认工作草案 r3
预算：已知小计/总额或未知/核验状态/约束状态
风险逐项列出；Mock、路线、营业、未预订为固定必要提示
[ ] 我已查看未知费用和风险，确认当前规划，理解没有完成预订
[确认 r3]  [返回修改]
```

L1/L2 按钮为“应用到工作草案”，不显示“授权保护项目”；L3 批准按钮须明确授权范围。拒绝成功后显示后端决定，失败不关闭提案冒充成功。整体确认勾选默认 false；披露刷新或版本变化立即清空勾选，禁止自动确认新版本。OVER_LIMIT/blocker/STALE 禁按钮并显示解决路径；unknown warning 可勾选后确认。

## 5. 组件、API 与状态复用

| 现有/新增模块 | 责任及实施任务 |
|---|---|
| 复用 App.vue、styles.css | Shell、语义布局；M1-02 接入旅行入口，不重做外观 |
| 复用 HealthStatus/useHealth | 仅用于服务存活展示；错误语义不改为业务 readiness |
| 提取 api/health.ts 的请求模式 | 新 `api/http.ts` 处理同源、超时、取消、错误包装与本地凭证；保留 health 兼容；M1-02 |
| 新 api/contracts.ts、trips.ts、planning.ts | OpenAPI 派生类型及业务响应运行时校验，拒绝未知/缺失关键字段；M1-02 起逐步增加 |
| 新 useTrip/useCommand/useGeneration | 读取与写状态分离；保存命令键/摘要，处理中禁止重复点击，超时用原键；后续读取可取消但写入取消不代表业务撤销 |
| RequirementsForm、RequirementSummary | 渐进输入、建议/用户事实分离；M1-02 |
| ClarificationCard | 一题、无偏好、修改入口、过期题处理；M1-03 |
| TripWorkspace、GenerationStatus | 无稿/生成/失败/重试/过期结果；M1-04 |
| ItineraryView、DaySchedule、PlanItemCard、HotelCard | 版本绑定结构展示、保护徽标；M1-04 |
| BudgetSummary、CostBreakdown、RiskList | 共用于草案/提案/确认/历史，纯展示只读；M1-04/05 |
| ChangeIntentInput、ProposalDiff、ProposalDecision | 意图输入、完整影响集合、L3 明确决定；M1-06 |
| ConfirmationReview、ConfirmedHistory、SnapshotDetail | 整体确认、分页历史、只读版本；M1-05/07 |

不把所有功能放进 App.vue；组件只发出意图，由 composable 调 API。展示 props 带所属版本，避免新预算配旧行程。状态以 `idle/loading/success/error` 联合类型沿用 useHealth 方式，读取使用 AbortController 和请求身份比较，卸载时取消读取；不能由旧响应覆盖新页面。

## 6. 异常、恢复和可访问性

无 Trip/跨 owner：统一不存在；数据库不可用：错误+重试，不放回示例数据。初次读取失败显示完整错误区；已有数据后失败可保留“上次读取”内容，标记过期并禁确认。契约失败不渲染部分金额为真实结果。生成失败保留需求，区分可重试与需改输入。后台重启导致运行中断后页面读 FAILED，而非永久转圈。

409 保留本地输入并展示“内容已变化，请重新查看”；冲突后旧授权/确认不自动重试。浏览器刷新从后端加载 intake、工作指针、快照及运行结果；本地缓存不能成为事实源。只有不含秘密的 pending 幂等命令可短期保存在 sessionStorage，刷新后核对摘要再重试；不保存本地 token，不用 localStorage 保存行程或授权事实。

状态变化用 aria-live=polite，阻塞错误可 role=alert；按钮真实 disabled，焦点返回错误摘要/新问题；颜色之外提供文本状态。400% 放大及 320px 宽度可完成主流程；表格不让确认按钮随横向滚动丢失。此轮只对布局文本检查覆盖，不声称浏览器视觉验收完成。
