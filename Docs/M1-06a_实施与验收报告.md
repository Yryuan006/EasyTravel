# M1-06a：行程修改、提案审阅与精确授权闭环

基线：`7fe4352c9d37cbebe8e57858d92b766f62345f44`。日期：2026-11-14（Asia/Shanghai）。本阶段完成后等待架构 Review，不进入 M1-06b。

## 已实现范围

新增真实持久化 API：

| API | 成功响应 | 说明 |
|---|---|---|
| POST `/api/v1/trips/{trip_id}/change-intents` | 202 GenerationRun | 双修订校验、冻结源工作稿和意图；只接受运行，不应用候选 |
| GET `/api/v1/trips/{trip_id}/proposals/{proposal_id}` | 200 ProposalView | 只读提案、完整结构化差异、费用、未知原因、风险、等级、完整范围及决定状态 |
| POST `/api/v1/trips/{trip_id}/proposals/{proposal_id}/decisions` | 200 DecisionResult | 明确 approve/reject，先重放持久化幂等回执，再校验当前业务版本 |

沿用 `GenerationWorker` 的领取、单执行者锁和启动恢复；没有第二套 Worker、内存队列或新的确认状态模型。CHANGE_INTENT 的 SUCCEEDED 只表示已产生 proposal_id，不能冒充已保存新工作稿。GET 不运行生成，不创建授权或决定。

确定性 Mock 只支持完全匹配的命令：“第二天安排轻松一点”，或“删除活动 / 替换活动 / 调整活动时间 / 添加活动 / 修改活动标题 / 更换酒店 + 项目 ID”。第一种替换第二天第一个活动；时间调整/新增模板为延后三小时，仍需通过重叠、日期和预算约束，不自动寻找可行时间。更换资源后的 Mock 费用置为未知并保存原因，不沿用为已核验报价。其他自然语言产生明确 FAILED `unsupported_change_intent`，不猜测理解。STALE 需求返回 `scope_replan_not_supported` 或修订冲突。

前端沿用 Vue 工作区与既有费用、风险组件，新增 `ChangeReview`、`useChanges` 与 API/运行时 schema。完整显示差异、预算、未知费用、系统风险、候选摘要与授权范围，默认不勾选；L1/L2 明确应用，L3 勾选后明确授权并应用，也可拒绝。HTTP 未确定时保留原 path/key/body，仅安全重放；决定回执已收到而 GET 核对失败时保留回执并只读恢复。身份切换清除内存并丢弃迟到响应。刷新后从真实 Trip 和最新运行读取新草案/决定，并保留历史确认指针的明确说明，不依赖浏览器持久存储。

## 领域复用与事务

未修改既有 Domain `models.py`、`rules.py`、`hashing.py` 的 v1 候选模型、分类与 hash。PlanService 只提取一个可在外层 UoW 内调用的 `apply_in_transaction`；原公开 apply 路径委托该方法，保持已有规则与回归。新增服务调用同一构造与分类函数，不由 Agent 或浏览器降级。所有酒店或受保护项目触发 L3，附带活动也计入精确集合。

批准事务锁顺序为 command → operation → Trip；先查 HTTP 回执，再读取提案/决定与双修订，核对 candidate_hash、不可变关联上下文和规则版本，重新构建候选及执行约束。L3 授权创建、单次消费、工作修订 CAS、追加版本/上下文、决定、操作回执与 HTTP 命令回执在同一连接/事务内完成；L1/L2 不创建授权。拒绝事务保存不可变决定及回执，不创建授权或新版本。已决定的提案用新命令再次决定返回 `proposal_already_decided`；同键同请求返回原响应。

工作修改只追加 draft_versions 与 draft_contexts，保留最新确认快照指针；当前修订显示 UNCONFIRMED。不改旧 ConfirmedSnapshot、旧预算或披露；不增加酒店保护/预订/支付事实。必须保留的系统 warning 重新生成，既有 blocker 不能由候选删除。

真实浏览器 → FastAPI → PostgreSQL 的三条连续链路：

1. 确认 r1 后提出普通活动修改 → L2 提案 → 明确应用 → r2/UNCONFIRMED；前后快照及披露完全一致，无具体授权；刷新后读取 APPLIED、新工作稿和旧确认指针。
2. 酒店修改 → L3 → 在 1280/390/320px 展示完整范围和风险 → 明确勾选授权 → 服务器已提交后模拟网络响应中断 → 原路径/键/内容重放 → 唯一授权且仅消费一次、唯一决定、唯一 r2。
3. 酒店提案明确拒绝 → 不创建授权或新版本 → 刷新读取 REJECTED。

HTTP 请求、状态、键、正文、响应及逐表 SQL 证据见 `M1-06a_HTTP与数据库证据.json`；不含 Authorization Token。截图：`M1-06a_普通修改成功.png`、`M1-06a_L3授权_1280.png`、`M1-06a_L3授权_390.png`、`M1-06a_L3授权_320.png`、`M1-06a_拒绝.png`。移动端断言页面无横向溢出，风险保持展开，图片已实际检查。
