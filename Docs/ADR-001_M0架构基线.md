## 边界

单一 Agent/模型适配器仅输出不可信的 `SafeChangeOutput`。它不能决定权限等级、授予授权、生成服务端操作 ID 或直接写数据库。Pydantic 校验后，领域规则基于当前工作草案计算候选及 L1/L2/L3，并检查时间、预算、酒店和已确认项目保护。

应用服务持有用户身份和事务边界。集成服务只绑定运行、提案、操作和用户决定；`PlanService` 负责具体授权、工作修改和整体确认。工作修改不等于整体确认，不产生订房状态。整体确认也不授予酒店修改权限。

LangGraph 负责节点顺序和等待。只有真实、摘要匹配且无任务错误的审批 interrupt 接受首次用户决定；resume 消息仅引用已持久化的决定。具体授权绑定提案、候选哈希、基础修订和项目集合。授权与决定原子保存；授权消费、工作修订和操作回执由 PlanService 在同一事务中提交。Checkpoint 与业务提交不是一个原子事务，靠稳定 operation_id 和业务回执恢复。

数据库保存业务事实并实施唯一约束、关联约束及确认快照禁止 UPDATE/DELETE 的触发器。图状态不能绕过业务服务的重新校验。当前身份固定为 `demo_owner`，不是正式认证和多租户方案。

| `spike02/workflow.py`、实验 Repository 的 `execute_experiment` | 仅保留实验和恢复回归；不作为正式计划写入入口，不修改旧图语义 |
| `m000/workflow.py` | 最小集成参考与验收夹具；正式图使用新的版本和数据迁移策略，不直接接管旧 Checkpoint |
| 各 Spike/M0-00 `database.py`、`schema.sql`、`worker.py`、Mock 与 seed | 专用实验设施；正式工程需配置管理、数据库迁移、连接生命周期和认证入口，不能原样发布 |

本轮 `m000-safe-change-v1` 使用独立的 `m000_checkpoint_v1` 和 `m000_business_v1` schema，直接复用现有 PlanService 及 Spike-03 DDL。没有移动、复制后改写或迁移旧 Checkpoint。未来保持旧图可恢复；不兼容变更另起版本，迁移需显式评审。

## 当前不支持

真实模型与提示词质量评估、真实酒店/景点/报价与实时证据、预订支付、正式用户认证/多租户、多实例或同一运行的并发执行、生产高可用均未实现。单进程锁只是本实验的串行执行约束，不是分布式锁。事务冲突检查与幂等通过不代表多实例并发已验收。

本轮不引入多 Agent、RAG、Celery、Redis 或完整前端。只完成 M0-00，后续任务等待 Review。
