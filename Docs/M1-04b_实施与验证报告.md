## 实现与契约

核对 M1-00 六份设计文档、ADR-001/002、M1-04a 实际 OpenAPI/生成服务/持久化结果，以及现有 Vue、API 客户端、澄清、Vitest、Playwright 和 PostgreSQL 测试。复用现有 ModelAdapter、Mock Planner、预算规则、GenerationWorker、事务、迁移器及本地可信身份。未新增依赖，未修改已应用 SQL 或旧 Spike 源码。

实施前选择见 `M1-04b_契约选择.md`。新增的唯一 API 是 `GET /api/v1/trips/{trip_id}/generation-state`：返回 trip_id、working_revision、source_run、latest_run。Repository 在已拥有 Trip 的短事务内读取，以当前工作修订关联 draft_contexts.run_id，核对 Trip、owner、intake、成功状态及 result.working_revision。预算原样读取来源运行的 diagnostics_budget，不从浏览器重算。来源缺失返回 null，不推断金额。没有数据库结构变更。

新增失败分类：known_costs_exceed_hard_limit、stale_input 的 retryable=false；invalid_output、worker_interrupted、persistence_failed 为 true。接受 retry_of 时再次按失败分类检查，历史 true 标志不能允许同输入超支重试。旧运行与原 202 回执不修改；新输入需使用当前 intake revision，不能引用旧输入的失败运行。

前端新增 api/generations.ts、useGeneration 和 ItineraryView、DaySchedule、PlanItemCard、HotelCard、GenerationStatus、BudgetSummary、CostBreakdown、RiskList。TripWorkspace 集成生成与只读展示；沿用现有 Shell、颜色、表单与身份机制。前端类型和运行时校验来自本轮实际 OpenAPI，兼容旧无 context 的只读稿。

## 交互与安全

仅用户点击才 POST。输入 READY_TO_GENERATE、无稿、无活动运行且状态已成功读取后才允许首次生成；编辑/需求冲突时不提供生成按钮。请求使用当前 expected_intake_revision、expected_working_revision=null、retry_of=null 或合法失败 ID，以及 UUID Idempotency-Key。

202 只表示接受。保存 run_id 后串行 GET，ACCEPTED/RUNNING 显示等待。成功后重新 GET Trip 和版本绑定预算。失败显示安全分类与下一步，不渲染失败候选；已有合法工作稿继续保留。网络/超时不换键，原命令保留在页面内存；双击有同步保护。同键重放仍读原 ACCEPTED 回执，再查询实时运行。明确未接受的版本冲突清除该待重放命令，要求读取最新状态后审阅。

每个请求带 AbortController 和递增请求身份，卸载及身份切换取消活动请求和轮询，旧响应不能覆盖新状态。新需求版本使旧读取失效。工作稿与来源预算修订不一致时拒绝组合展示；失败诊断预算仅在 intake 匹配时展示。刷新仅 GET，重新输入凭证后从 PostgreSQL 恢复；没有浏览器草案 seed、可信输出提交或权威预算累加。

Token 沿用现有页面内存机制，不写 URL、localStorage、sessionStorage、IndexedDB、日志或构建变量。更换身份卸载旧工作区。跨 owner 的 Trip、运行与新投影返回安全 404；生成运行仍绑定父 Trip。

按 Asia/Shanghai 日期与时间排序展示 1–5 天活动；跨夜酒店独立展示入住/退房、房型与房间数，不参与前端活动冲突推断。费用显示所属项、类别、金额、Mock 标志与未知原因。所有 Mock 内容有“模拟建议，尚未核验”，交通文本不创造真实车次、公交线路或营业信息。

预算展示服务端已知小计、总额或“总额暂无法确定”、生成时硬上限、当前上限变化及两个预算状态维度。金额仅分转元，不再次展开人数/间数/晚数。null 显示未知，明确 0 显示 ¥0.00；小计可能含估算，不称为已核验总价。风险展示结构化 GenerationNotes 与未核验路线/酒店、未预订说明。STALE 工作稿明确保留旧需求预算，不用于当前需求。当前稿未确认、历史确认指针、NOT_ASSESSED 与未预订分开说明。

## 数据库隔离偏差与最终重跑

必须记录的偏差：最初两次全量运行沿用了 M1-04a 脚本的 `.env`，其中旧 Spike 回归固定连接既有 `easytravel_env00_test`，向它追加了新的随机测试线程/运行。正式 API、生成、兼容和浏览器测试都使用本轮新库；没有删除、清空或重置旧库，也没有修改旧 Spike 源码或旧 SQL。此前追加的实验测试记录保留，没有为“恢复干净”而删除。**因此不能声称整个本轮对所有既有库零写入；这不符合用户本轮隔离要求，应交由 Review 明确审查。**

修正后，最终 358 项回归运行在新物理 PostgreSQL 集群 `easytravel-m104b-isolated-db8334a61a`、新数据卷及独立 55433 端口。旧库固定端口防护保持原源码；仅本次 Python 测试进程通过临时 sitecustomize 将 psycopg 的名义 55432 连接映射到新 55433，包括测试子进程。临时 .pth 在 finally 中移除，普通应用不使用该映射。既有 ENV-00 未停止，最终重跑期间其 24 张实验/Checkpoint 表的行数和全行哈希完全相等。这份最终证明不能追溯抹去前两次追加。

停机接管 55432 的备选方案被自动审批拒绝（会中断既有测试服务），未执行；随后采用上述独立端口方案通过全部回归。新库、容器和卷均保留；隔离回归容器已停止，既有 ENV-00 仍运行。凭据只在 ignored `.local`，不在提交中。

## 复现入口与限制

- 前端：在 frontend 下运行既有 typecheck、build、test 命令；本项目使用 `.tools/node-m003/node_modules/node/bin/node.exe`。
- 浏览器：先用 prepare_m002_test_db.py 创建新的 `.local/<名称>.env`，再运行 `.venv/Scripts/python.exe scripts/verify_m104b.py --database-env .local/<名称>.env`。脚本显式迁移、启动其 HTTP/Vite 子进程、执行完整 Playwright、独立核对 PostgreSQL，最后关闭它创建的进程。不会启动生产多 Worker。
- 全量后端隔离复现：`.venv/Scripts/python.exe scripts/verify_m104b_isolated.py`。需要独立 55433 端口空闲；创建新随机容器、卷、角色和库，保留资源，不重置已有数据。Windows Python 3.12 测试工具；原 guard 的端口检查不改，实际传输映射仅用于这次回归。直接使用 verify_m104b_backend.py 时必须显式提供 experiment-env、retained-env 和全新数据库前缀，不再隐式读取旧实验配置。
