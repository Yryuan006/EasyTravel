# M1-00：API 契约草案

日期：2026-11-11。状态：供架构 Review，**不是当前运行接口**。正式现状仅有 `/api/v1/health`。沿用 FastAPI 路由和统一错误包装，不调用第三方服务。

## 1. 端点索引与数据契约

下表请求/响应名称对应第 6 节 OpenAPI 的严格 schema；它们同时是后续 Pydantic DTO 和 TypeScript 类型的命名依据。OpenAPI 是本草案的字段权威来源。所有对象禁止额外输入字段；复用的领域输出 schema 直接由当前 Pydantic 模型导出，既有模型中的跨字段 validator 仍须执行，不能只用 JSON Schema 验证代替。

| Method | 相对 `/api/v1` Path | 请求 DTO | 响应 DTO | 正常 HTTP | 业务动作 |
|---|---|---|---|---|---|
| POST | /trips | CreateTripRequest | TripView | 201 | 保存旅行和首个需求收集版本，不生成草案 |
| GET | /trips/{trip_id} | 无 | TripView | 200 | 读取旅行、最新输入、工作稿和最新确认指针 |
| PUT | /trips/{trip_id}/requirements | UpdateRequirementsRequest | TripView | 200 | 全量保存新输入；旧工作稿保留并标需求过期 |
| GET | /trips/{trip_id}/clarifications/next | 无 | NextQuestionResponse | 200 | 读取下一必要问题；GET 无写入或生成副作用 |
| POST | /trips/{trip_id}/clarifications/{question_id}/answers | AnswerRequest | TripView | 200 | 回答绑定输入版本的问题并推进需求版本 |
| POST | /trips/{trip_id}/generations | GenerateRequest | GenerationRun | 202 | 冻结输入，接受首次生成或重规划运行 |
| GET | /trips/{trip_id}/generations/{run_id} | 无 | GenerationRun | 200 | 读取运行结果；失败也返回200并显式FAILED |
| GET | /trips/{trip_id}/confirmation-preview | 无 | ConfirmationPreview | 200 | 读取当前预算和风险；有稿但超预算或过期仍200并禁止确认 |
| POST | /trips/{trip_id}/confirmations | ConfirmRequest | ConfirmResult | 201 | 用户明确确认当前草案、预算和风险 |
| POST | /trips/{trip_id}/change-intents | ChangeIntentRequest | GenerationRun | 202 | 意图转为不可信候选，不能直接应用 |
| GET | /trips/{trip_id}/proposals/{proposal_id} | 无 | ProposalView | 200 | 查看差异、候选、等级、范围和风险 |
| POST | /trips/{trip_id}/proposals/{proposal_id}/decisions | DecisionRequest | DecisionResult | 200 | 明确应用或拒绝；L3批准含精确授权并原子应用 |
| GET | /trips/{trip_id}/snapshots | 无 | SnapshotPage | 200 | 历史确认版本，按确认时间与snapshot_id倒序游标分页 |
| GET | /trips/{trip_id}/snapshots/{snapshot_id} | 无 | SnapshotView | 200 | 读取不可变源修订、当时输入和披露 |

所有成功响应 `Cache-Control: no-store`；读取 200，创建/确认 201，运行接受 202（并非行程已生成），决定 200。重放返回原 HTTP status/body；同源父子资源必须同时核对 Trip 及 owner。列表默认 20、最多 100 条，游标不可信，服务端校验 owner/Trip、排序键与范围；非法游标 422。没有自由指定 owner 的查询参数。

## 2. 用户意图与服务端权威

浏览器可提交需求、自然语言意图、看到的摘要/版本、明确同意或拒绝；不能提交 actor/owner、Trip/operation/proposal/authorization 新 ID、confirmed/booked、保护 hash、服务端等级、预算核验结论、可信 Evidence 或最终候选。不可接受 `WorkingDraft`/`ChangeProposal` 作为写请求。未知字段一律 422，而非悄悄忽略。

`explicit_confirmation=true` 与 `explicit_authorization=true` 是当前用户主动点击产生的意图，不是客户端签发的授权结果。服务端从本地认证依赖得到 actor，核对拥有权、版本、精确候选和范围后才写业务事实；Agent 不可调用批准/确认入口，也不能在它的结构化输出携带这些字段。

确认、修改意图与决定请求必含非 null expected_working_revision；收集与生成允许 null 表示尚无稿。explicit_confirmation 必须严格布尔，false 业务拒绝409，只有 true 可提交。L3 批准必须 explicit_authorization=true；L1/L2 必须 false，不生成授权记录。Approve 的 item_ids 必须与服务端 touched_item_ids **完全相等**（规范排序后比较，含附带改变的活动），拒绝请求不接受授权字段。拒绝后再批准同提案 409；再次决定需要新提案，不能篡改旧决定。

输入 `Answer.value` 的实际类型由 field_key 校验：人数只接受1/2、天数1–5、日期按 TravelDates、预算整数分；自由文本不可灌入金额字段。NextQuestion 在创建/更新/回答事务中预生成并保存，GET 只读取。question=null 表示无下一题，仍应看 blocking_fields/collection_status；不代表已经生成。

`GenerationRun.result` 在 SUCCEEDED 时必须恰有一个非 null 结果：首次为 working_revision，重规划/修改为 proposal_id；其他状态 result=null。FAILED 必有 error，其他状态 error=null。accepted/running 为持久化处理状态，不是领域阶段。失败结果 GET 返回200；无法接受请求（缺输入/旧版本等）直接409且不创建运行。最多一次活动运行/Trip，另一新请求409 generation_in_progress。

`ProposalView.context_v2=null` 时 proposal 必须为既有 ChangeProposal；非 null 时必须为 ReplanProposal，Pydantic 需做配对校验。candidate_notes 始终来自不可变 proposal_contexts，并与context_v2.notes一致（如有），不能在审批后变化。为避免改变旧 v1 candidate_hash 算法，v1 notes 以服务端生成的提案 ID 绑定不可变关联上下文；批准服务必须核对该关联记录和风险规则版本，不得换用当前生成的新说明。v2 candidate_hash 覆盖 proposal（排除自身hash）及完整 context；基础 requirements_revision 不偷换成候选版本。ReplanProposal.output.kind=requirements_replan，不能用需至少一次操作的旧 SafeChangeOutput 表达仅预算/偏好改变。完整候选与旧稿在服务端计算差异，touched_item_ids 为新旧稿全部项目的并集，统一L3；内容hash未变化的项目保护仍保留。需求重规划未交付时409 scope_replan_not_supported。

`ConfirmationPreview` 有稿时即使 OVER_LIMIT/STALE 也返回200并给 blocking_reasons；pending_requirements_budget 是当前稿在最新明确预算下的诊断，仅供显示、不覆盖原稿预算。它若不适用（未定硬上限或日期不兼容）为null，并给阻塞原因。无稿409 draft_not_ready。现有 confirmation_preview 会先 check_constraints 抛错，此 HTTP 用例需先 evaluate_budget 生成可审查披露，并在提交时继续硬拦截；不是现有方法可直接原样挂路由。

风险来自版本上下文及确定性规则；同一披露包含 Mock、未预订、路线/营业未核验、未知成本等必要提示。seen_disclosure_hash 绑定已有预算/稿/需求，seen_risk_hash 绑定上下文/输入/风险规则版本；服务器重新计算二者并在确认事务保存风险正文。legacy context=null/risk_disclosure=null 是缺记录，不能被新页面补造已看过的事实。

## 3. 幂等、并发和错误

每个 POST/PUT 必带 UUID 格式 Idempotency-Key。键作用域为可信 owner+method+规范 path；请求摘要覆盖 body（包括 expected revisions 和用户明确决定），不包含 token。首次生成服务端 command_id/operation_id；浏览器绝不能提交 operation_id。相同键同摘要在重启/并发后返回原结果，先于 revision 检查；相同键换 body 返回409 idempotency_key_reused。创建时在 Trip 尚不存在前也要可占键，同事务完成命令回执与 Trip/输入写入。不可回收旧键后产生新副作用。

请求处理中同键可等待有界短事务或返回409 command_in_progress，携 Retry-After；该409不是成功回执，前端保留原键重试。业务提交失败则全回滚；尚无成功回执可原键重试。202 的原回执始终指向同一 run（可能仍是原 ACCEPTED 表示），实时状态用 GET run，不以重放 body 更新运行。已 FAILED 要显式新键 retry_of；retry_of 仅允许同 owner/Trip/输入且 FAILED，不能重试已成功运行。

expected_intake_revision 与 expected_working_revision 分别检查；null 只表示调用者看到尚无草案。如果已存在稿而提交null，409；旧 question/proposal/hash 亦409。拒绝旧提案也要求刷新，不能在拒绝时悄悄接受过期的其他内容。命令锁→operation锁→Trip锁→proposal决定检查保持固定顺序。应用/批准/确认再做领域约束校验。确认同一源修订使用新键也不产生第二个快照（既有唯一约束），返回同快照；若披露已变化则409 snapshot_disclosure_conflict。

| HTTP | 稳定 error.code（设计新增 allowlist） | 前端动作 |
|---|---|---|
| 401 | authentication_required | 显示本地连接身份未就绪，不重试换用户 |
| 403 | origin_not_allowed / local_only_api | 提示环境不允许，不提供绕过 |
| 404 | resource_not_found | 不区分不存在与他人数据 |
| 409 | stale_intake / stale_revision / stale_question / stale_proposal | 刷新，保留本地输入，旧批准失效 |
| 409 | requirements_incomplete / draft_not_ready / scope_replan_not_supported / generation_in_progress | 显示补充或等待路径 |
| 409 | known_costs_exceed_hard_limit / blocking_risks / disclosure_not_acknowledged / risk_not_acknowledged | 禁止确认，重新审阅或修改 |
| 409 | explicit_confirmation_required / specific_authorization_required / authorization_scope_mismatch / proposal_already_decided / snapshot_disclosure_conflict | 说明决定或授权冲突，不自动替用户批准 |
| 409 | idempotency_key_reused / command_in_progress | 前者纠正客户端；后者原键有界重试 |
| 422 | invalid_request | 输入形状/严格类型/日期范围/多余字段错误；不回显原 body |
| 503 | business_dependency_unavailable | 原键重试；health alive 不掩盖 DB 不可用 |
| 500 | internal_error | 通用错误，保留请求键，不显示内部异常 |

包装沿用 `{"error":{"code":"…","message":"…"}}`。M0 当前只把 BusinessConflict 映射 business_conflict；未来须按显式 allowlist 映射上述 code，不把异常字符串直接外泄。请求 contract 不合法用422；已有合法输入但业务条件不足用409。异步失败 error.code 为 invalid_output/refusal/adapter_timeout/adapter_unavailable/constraint_violation/stale_input/worker_interrupted，retryable 按原因由服务端定；结构坏输出不能退化为自由文本行程。首次超支生成只返回失败运行及 diagnostics_budget，不伪装正常草案。

## 4. 本地身份与公开部署限制

新增 local/test 业务开关，默认关闭；启用时必须配置服务端生成的高熵不透明 bearer token→固定 local actor 映射；actor 不来自 body、query、X-Actor 或浏览器任意 header。每个开发身份独立 token/actor/数据命名空间，不能所有访问者共用公开 demo_owner。只允许受信任本机操作者；同一桌面掌握 token 的人即拥有该本地身份，不宣称已解决操作系统多用户隔离。

token 由本机受限文件/进程配置提供给开发者，在浏览器开发连接入口手动输入并仅保存在内存；不提交 Git、不输出日志、不放 URL、VITE_* 编译变量、localStorage、页面源码或通用 Vite 自动注入。不新增用户注册/登录产品页。刷新后可要求重新输入本地凭证；命令重试键不是凭证。

后端与 Vite 仅绑定127.0.0.1；限定 Host 与精确 Origin（开发为 http://127.0.0.1:5173），禁止通配 CORS。浏览器请求经现有同源 `/api` 代理并携 Authorization，服务端拒绝不允许的 Origin；写请求有 Origin 必校验，CLI 无 Origin 仍必须 token。bearer 不由 cookie 自动附送，降低跨站触发；loopback/Origin 本身都不能替代 token。业务 API 禁外网监听、隧道和共享预览。

正式认证接入及所有权/CSRF（如改 cookie）/会话生命周期、限流、TLS、运行/迁移角色隔离验收之前，本草案**所有旅行、需求、澄清、运行、披露、确认、提案和历史读写 API 都不允许公开部署**。现有只报存活且依赖 not_checked 的 health 保持原语义。新增业务身份配置须独立扩展 Settings，不能假设当前仅 local/test 的配置已支持 token。

## 5. Pydantic / TypeScript 实施约定

Python DTO 统一 `ConfigDict(extra='forbid', frozen=True, strict=True)`；金额/修订用 StrictInt 或 strict Field，确认意图用 StrictBool 再校验 True。不要用 Literal[True] 的宽松转换接受1或字符串。JSON date/date-time 从 JSON 解析，经 validator 校验 +08:00、1–5 天和字段互斥；复用领域验证。所有读取 DTO 为只读投影，Pydantic 运行时校验输出。

```python
# 后续代码示意，本轮没有新增模块
class ConfirmRequest(BaseModel):
    model_config = ConfigDict(extra='forbid', frozen=True, strict=True)
    expected_intake_revision: Annotated[int, Field(strict=True, ge=1)]
    expected_working_revision: Annotated[int, Field(strict=True, ge=1)]
    seen_disclosure_hash: Annotated[str, Field(pattern=r'^[0-9a-f]{64}$')]
    seen_risk_hash: Annotated[str, Field(pattern=r'^[0-9a-f]{64}$')]
    explicit_confirmation: StrictBool
    # 应用用例检查 explicit_confirmation is True，否则409 explicit_confirmation_required
```

```ts
// API类型最终从冻结后的OpenAPI派生；现有health的运行时校验模式继续沿用。
interface ConfirmRequest {
  expected_intake_revision: number
  expected_working_revision: number
  seen_disclosure_hash: string
  seen_risk_hash: string
  explicit_confirmation: true
}
type Answer<T> = {state:'unanswered'|'no_preference'; value:null}
  | {state:'provided'; value:T}
type ApiErrorResponse = {error:{code:string; message:string}}
// 其余 DTO 与下方 components.schemas 同名；金额 number 必须是安全整数，null 不得归零。
```

首切片无需安装类型生成器：可用仓库脚本从冻结 schema 生成/验证 TS，并记录同步检查；选新工具需独立评审，不默默加依赖。编译类型不能代替响应解析，HTTP成功但字段非法须 contract error。实际 FastAPI 生成 OpenAPI 与本草案比对后才算接口验收。
