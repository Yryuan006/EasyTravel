# M1-08：剩余能力与下一阶段建议

本轮只证明当前本地单执行者的 Mock 旅游规划核心闭环符合阶段验收要求，不代表真实路线研究完成或完整商业 MVP 已上线。M1-08 交付后等待 Review；下列只是建议，不构成 M2 授权。

## 本轮明确未实现

- 真实 LLM、提示词/模型质量评估、真实旅游研究、地图和路线可行性、酒店/交通/营业时间及实时票价接口。
- 酒店预订、支付、出票、订单履约、取消退款或出行准备清单；整体确认始终不代表这些事实。
- 生产身份认证、会话生命周期、数据库 RLS、部署级密钥管理、迁移/运行角色分权与公开部署。
- 恢复历史为工作稿、直接编辑历史、完整提案历史导航、单项保护创建/撤销 UI；未来必须分别设计明确的版本与授权用例。
- 多 Agent、RAG、Redis、Celery、多 Worker、分布式锁及多实例调度。

## 保留限制

| 限制 | 当前行为与使用影响 |
|---|---|
| Mock 语义范围有限 | 修改意图只支持界面列明的确定性命令；保存偏好并不证明真实满足偏好或路线可行性 |
| 本地凭证只在内存 | 刷新需要重新提供；不确定写请求的内存重放信息离开页面会丢失，应先读取服务端事实 |
| 单执行者保守恢复 | Worker 重启把未完成 ACCEPTED/RUNNING 标为 worker_interrupted；显式新键 retry_of 后才能重试 |
| 游标签名密钥为进程内存 | API 重启后旧分页游标 422，需从第一页重读；历史事实及直达详情 URL 不受影响 |
| 历史字段可能缺失 | context/disclosure 缺失明确标注，不回填用户输入或风险审阅事实 |
| 性能范围有限 | 已验收小型本地旅行与 105 条历史分页，未进行生产负载、大数据量、数据库灾备或宿主断电验收 |

## 建议的评审顺序

1. 先 Review 本轮六份文档、D01 最小修复、E01～E22 证据和隔离记录，确认当前 Mock 核心闭环阶段可以归档。
2. 若考虑公开使用，另行设计生产身份与部署/密钥/运行角色边界；不要直接公开当前本地 Token 入口。
3. 若考虑真实数据，先定义供应商来源、价格适用范围/时间、新鲜度、失败披露、授权与预算保护、可重复测试和评估标准，再单独批准接口实现。
4. 若考虑恢复历史、预订支付或多执行者，应分别提交独立提案与事务/授权设计；不能从“当前已确认规划”自动推导这些新权限。
