## 交付代码及 Schema

迁移策略及成本见 `ADR-002_正式数据库迁移与持久化.md`。采用显式顺序 SQL + 事务迁移台账 + SHA-256 校验和 + advisory lock。正式 schema 为 `easytravel`，包括 7 张业务表和 1 张迁移台账。

| easytravel/backend/infrastructure/migrate.py | 显式原子升级、并发安装锁、历史/校验和验证、安全 CLI 退出状态 |
| easytravel/backend/infrastructure/database.py | 独立显式配置、目标校验、连接生命周期、连接失败诊断 |
| easytravel/backend/infrastructure/repository.py | 完整 schema 限定的 SQL、所有权过滤、行锁、CAS、回执与授权数据访问、UoW 适配器 |

| easytravel/backend/application/plans.py | 创建初始草案、读写持久化、提案/授权、整体确认的应用事务协调 |

首个迁移 SHA-256 为 `71dad1b913d25acfe2a7f0e3cf96e8c7370e65c54855240023c64c8dbd1b7b43`，与数据库台账实测相同。

工作草案的完整内容保存在不可变 `draft_versions`；`working_drafts` 只保存当前修订和最新确认指针。`confirmed_snapshots` 引用同 Trip/所有者的不可变修订，因此读取快照可还原当时的 requirements/payload/item_confirmations。快照和源版本均禁止 UPDATE/DELETE/TRUNCATE，同 Trip/源修订只能确认一次。授权通过复合外键绑定提案、候选摘要、基础修订、项目集合及所有者，消费仅允许一次，消费到回执的关联延迟至提交检查。

应用服务通过注入 UoW 定义事务范围。Repository 不提交，每个用例持有独立连接；成功退出提交，SQL/领域异常及提交失败回滚，连接随后关闭。操作锁先于 Trip 锁；重试先查回执，再检查旧修订，已提交的业务结果可跨进程读取。没有进程级全局连接、连接池或迁移副作用。

正式 Domain/Application 不依赖 psycopg/FastAPI/LangGraph 或任何 Spike/M0-00 包；继续复用根目录纯契约、预算/披露函数。旧 Spike/M0-00 源码、DDL、测试和 Checkpoint 恢复语义均未改动。

正式连接必须显式提供 `EASYTRAVEL_DATABASE_URL`，不读取旧测试变量或自动加载 `.env`。旧 ENV-00 库及系统库被拒绝。所有业务 SQL 完整限定 easytravel schema，连接 search_path 为 pg_catalog。模块导入、应用工厂和 HTTP 健康检查均不连接数据库或执行迁移；原有离线反例测试继续通过。健康检查仍仅报告应用存活和 database=not_checked。

## 复现

先使用新文件名创建一个空测试库（需要访问已授权 Docker 实例），保留已有库与凭据：

```powershell
.venv/Scripts/python.exe scripts/prepare_m002_test_db.py --env-file .local/m002-review-01.env
$env:UV_CACHE_DIR = Join-Path $PWD '.cache/uv'
$env:UV_PYTHON_INSTALL_DIR = Join-Path $PWD '.tools/python'
$env:PYTHONUTF8 = '1'
.tools/uv/uv.exe run --frozen --no-sync --env-file .env --env-file .local/m002-review-01.env python -m pytest -v -s
```

新测试模块要求空库，测试本身先执行显式迁移；不要在同一个测试库重复跑完整模块。每次需要新库/新凭据文件，脚本不会删除旧资源或覆盖既有文件。单独验证 33 项可将 pytest 参数改为 `tests/backend/test_persistence.py -v -s`，仍需另一个空库。

人工运行迁移使用现有保留的专用库即可，重复运行不会破坏数据：

```powershell
.tools/uv/uv.exe run --frozen --no-sync --env-file .local/m002-final.env python -m easytravel.backend.infrastructure.migrate
```

配置/凭据错误和数据库不可用会明确失败；不会自动创建数据库、切换到实验库或使用内存替代。创建新数据库的测试准备脚本与正式升级器分离。
