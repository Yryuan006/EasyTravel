## 实现与事实边界

新增 `application/snapshots.py`、`domain/snapshots.py`、`infrastructure/snapshots.py`，通过原连接生命周期、Repository 基类和 UoW 约定查询既有表。列表返回 SnapshotPage，详情直接复用 SnapshotView/ConfirmedSnapshot。未改既有确认事务、Plan Repository、快照结构、预算/风险算法或迁移 001～007；不增加迁移。

两个正式 GET 路由均使用可信本地 actor、禁止缓存。列表在只读 REPEATABLE READ 事务先检查 Trip/owner，再按 `(confirmed_at DESC, snapshot_id DESC)` 查询 `limit+1`；默认 20、最多 100 条，仅返回本页，使用最后一条的位置继续查询。已有 Trip/源修订唯一索引能缩小到单 Trip，本阶段 105 条同时间戳历史验证未显示需要新索引；不声称已经完成大规模历史数据性能验收。

游标为规范 base64url 编码及 HMAC-SHA256 签名，绑定版本、Trip、actor、精确确认时间和 snapshot_id。篡改、非规范编码、跨 Trip/owner、空游标、超长参数、重复参数、未知参数均拒绝。仅历史列表精确开放 `limit`、`cursor` 查询参数，其他原有身份入口仍拒绝查询参数和伪 actor。游标不携带访问授权。

详情 SQL 同时核对 snapshot_id、trip_id、confirmed_by，并复合关联 Trip、不可变 draft_versions、confirmation_disclosures、draft_contexts。完整需求、行程、项目确认及预算均读取确认时事实；不读取当前工作稿替换历史内容。优先使用确认事务保存的 context；缺少时只读取同一不可变来源修订的 context；两处均缺失则为 null。风险披露仅来自 confirmation_disclosures，绝不从生成备注或当前规则推造用户曾经审阅的事实。readiness 固定 NOT_ASSESSED，booked 固定 false。

GET 事务明确设置数据库 READ ONLY，不创建快照、修改指针、推进修订、消费授权、执行模型或迁移。兼容已升级正式数据库中的 M0-02 旧快照，不要求旧数据库永久停留在 001-only schema；缺少查询所需正式表时按业务依赖不可用返回 503。

## 页面与契约

Vue 原轻量 URL 路由增加 `/trips/:tripId/history` 与 `/trips/:tripId/history/:snapshotId`，工作区提供“查看确认历史”。新增 TripHistory、useHistory 与 snapshots API 客户端，复用 ItineraryView、DaySchedule、HotelCard、BudgetSummary、CostBreakdown、RiskList；展示组件只增加历史展示模式，预算不在浏览器重算。

列表提供分页加载，详情展示快照 ID、来源 rN、确认人/时间、当时正式需求、已保存输入 iN、每日活动、酒店、费用、确认时预算与未知费用、保存的风险披露和生成备注。未回答、用户明确无偏好、未记录分开显示；缺少 context/disclosure 明确显示“此历史版本未记录相关信息”。生成备注不冒充风险审阅记录。历史页面没有修改、恢复、授权、支付或预订操作，提供返回列表/当前工作区。

Token 仅在原页面内存。身份/Trip/快照变化及卸载时取消读取、推进请求 epoch、清空数据和状态；迟到响应不能覆盖新页面。读取错误不制造空历史或成功快照；分页失败可重新从第一页读取。HTTP 401/403/404/422/503、超时、断网、非法 JSON/契约和错误父资源都有明确失败处理。前端对每次返回执行实际 OpenAPI schema 校验；SnapshotView 复用既有 TypeScript 确认契约，仅新增 Summary/Page 类型与两个 schema，全部 30 个可达 schema 对照实际 OpenAPI。

实际 OpenAPI：`M1-07_OpenAPI.json`；可重复运行 `python -m scripts.verify_m107_contract`。核对结果：`M1-07_契约与迁移核对.json`，包含 M1-00 字段/required、前端运行时 schema、分页参数与 001～007 SHA256。SnapshotSummary 是 M1-00 SnapshotPage 内联条目的命名提取，内容相同。
