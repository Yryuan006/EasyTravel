# M1-00：端到端验收场景

日期：2026-11-11。以下是后续实现的验收契约，**本轮未执行这些端到端测试**。M0 测试通过不能替代本清单。

共用夹具：本地可信身份 A/B、独立正式测试库（显式迁移）、固定时钟、Mock Adapter，无外部服务。示例 A 上海→杭州，2026-12-04～06，3 天2晚、2 人、1 间双人房，目标 200000 分、硬上限 230000 分，公共交通、安静干净、不爬山。日期及价格均测试数据。对 UI 用 Playwright，对规则用 pytest，对事务用真实 PostgreSQL；不以截图代替数据约束断言。

| ID / 场景 | 前置条件 | 操作 | 预期状态与不变量 | 验收方式 |
|---|---|---|---|---|
| E01 完整信息创建 3 天旅行 | A 有本地身份，库无该请求 | 填共用夹具，保存，再 GET | 201；一个 Trip、intake i1、working=null；输入已持久化且 READY_TO_GENERATE；尚未生成/确认 | API+DB 行数、字段；UI 重载摘要 |
| E02 缺预算 | 其他必需信息完整，硬上限 unanswered | 保存并获取下一问题；尝试生成 | 仅问硬上限；无默认为 0/目标预算/无限上限；生成 409 requirements_incomplete、无运行；“没偏好”可存但继续阻塞 | UI 文案+API+DB 不产生草案 |
| E03 修改日期 | i1 为 12/04～06，尚无稿 | 改 12/11～13，带 expected intake=1 保存 | i2；旧 i1 不变；日期和天数一致；i1 的问题/生成请求失效 | API CAS、不可变版本对比、UI 摘要 |
| E04 合法结构化生成 | 输入足够，working=null | POST generation，同一 run 轮询 | 202→SUCCEEDED，r1/requirements r1；items/costs/notes 合法、输入来源可还原；无确认快照；费用为 ESTIMATED 或 INDETERMINATE | pytest 结构/规则，API 查询，DB 原子写入，UI 每日展示 |
| E05 非法 Agent 输出 | Mock 重复键、非法 JSON、悬空成本、漏酒店字段等逐一参数化 | 触发生成，最多一次修复仍失败 | FAILED invalid_output；无工作指针/半稿/快照；仅脱敏诊断；UI 失败、不展示成功 | 适配器调用计数，API run.error，DB 零新增草案；检查日志无原文 |
| E06 部分费用未知 | 合法稿含 amount=null/category=unknown/reason | 展示预算并获取披露 | total=null，INDETERMINATE、unknown IDs；已知小计含估算且正确；未知不显示 0；risk warning；若无 blocker 可明确接受后确认，但不 READY | 规则金额断言、UI DOM 文本、确认后快照预算 |
| E07 已知费用超硬上限 | 未确认稿；用户明确降低上限低于已知小计 | 保存需求、查看披露/尝试重规划和确认；另用超支首次生成反例 | 原稿仍在且 STALE；pending budget 显示 OVER_LIMIT；正常确认 409。超支候选不能应用，首次超支生成 FAILED，无合法首稿；L3 批准也不能豁免 | API 409 code、预算评估单测、DB 快照/版本数不变、UI 禁确认 |
| E08 确认当前稿 | r1 输入同步，预览无 blocker且未超支 | 读披露；勾选确认，提交准确 revision+两个 hash | 一份不可变 S1，source r1；指针 S1；确认披露同事务；booked=false、NOT_ASSESSED；item_confirmations 不因整体确认自动增加 | UI→API→DB；UPDATE/DELETE 快照及源版本拒绝的既有回归；读取上下文 |
| E09 普通活动修改不改快照 | S1 源 r1，活动未保护 | 提“第二天轻松一点”，看 L2 后应用 | r2；最新快照仍 S1且内容/hash/源修订不变；当前未确认；风险/费用重算；不修改酒店 | 提案 diff+API 回执；DB 前后比较；UI 双版本标识 |
| E10 保护酒店等待授权 | r1 含酒店 H（不依赖是否有整体确认） | 请求换酒店并读取提案；提交缺 explicit_authorization 的批准 | L3、精确影响集合；未明确授权时 409 specific_authorization_required；工作稿/授权消费不变 | UI 按钮文案，API 反例；DB 未推进 |
| E11 拒绝提案 | L3 P 待决定 | explicit decision=reject，刷新页面 | P 显示 REJECTED；没有新授权/消费、工作稿、快照；重开可读拒绝；再批准相同 P 409 proposal_already_decided | API+DB+重启读取；UI 当前稿不变 |
| E12 重复提交 | 创建、回答、生成、修改、确认、批准/拒绝各一请求 | 同键同 body 并发/断网后重试，再以同键换 body | 同请求回原 HTTP 结果与同 ID；不重复 Trip、运行、提案、版本、快照、授权或决定；不同请求 409 idempotency_key_reused | 参数化 API 并发及重启重放；DB 唯一约束；UI 双击/超时 |
| E13 旧 revision | 读 i2/r2，另一路已推进 i3或r3 | 用旧版本更新/生成/应用/确认 | 409 stale_intake/stale_revision；无新副作用；前端保留输入并要求重审；已成功同键重放先返回原结果 | CAS/并发 API；UI 冲突反馈；DB 行数 |
| E14 后端不可用 | UI 已打开；另测首次无数据 | 断连或受控 503，执行读取/保存/确认 | network/timeout/http 错误；不生成假数据、不显示成功/确认；已有数据标过期；恢复用原键查询结果 | Playwright 路由中断/503；命令键保持；恢复后 GET 对照 |
| E15 重新打开 | A 已有 intake、稿、S1、决定 | 关闭页面/重启 API 后重新访问 Trip/history/proposal | 从 PostgreSQL 读回一致输入、rN、S1、披露与决定；不是内存 seed；运行中断明确 FAILED | 独立进程读取+Playwright reload；持久化行验证 |
| E16 身份与越权 | A/B 独立本地 token，A 有 Trip | 无 token、伪 actor/header、B 读写 A 的各子资源 | 401；未知 actor 等字段 422；跨 owner 404；不泄露 run/proposal/snapshot 存在性 | API 全端点矩阵；检查响应不带堆栈/DSN/token |
| E17 披露变化 | r1 preview 已取；同一版本风险规则/预算证据已变化 | 提交旧 disclosure_hash 或 risk_hash | 409 disclosure_not_acknowledged/risk_not_acknowledged；无快照；UI 清空确认勾选 | 固定时钟/规则版本测试、API、DB |
| E18 精确授权原子性 | L3 P 影响 H+A | 少一个 ID、错 hash、多一个项、复用旧授权；合法批准后人为触发 COMMIT 失败 | 错范围全部拒绝；合法批准仅消费一次；提交失败 decision/grant/消费/版本/回执/上下文全回滚 | 真实 DB 故障注入、复合 FK及并发回归 |
| E19 日期变更后的重规划 | S1 源 r1、i1；保存新日期成 i2 | 发重生成，Mock 得新候选，审批前后查询 | 生成成功返回 v2 L3 proposal，审批前仍 r1/S1；批准后 r2、requirements r2、context i2；S1 不变；旧日期报价不可继承为核验 | v2 schema/hash/作用域反例；API/DB；若未交付 v2 则 409 scope_replan_not_supported |
| E20 生成过时与进程中断 | run 捕获 i1/r1，未完成 | 另端保存 i2；或中断生成进程 | 旧结果 FAILED stale_input不覆盖；重启 RUNNING→FAILED worker_interrupted；原稿保留；显式新键 retry_of 后仅一个新运行 | 同步屏障 API 测试；独立进程恢复与唯一活动运行约束 |
| E21 输入及范围 | 1天/5天边界、6天、3人、目标>上限、日期矛盾、免费及 unknown 混合 | 保存/生成并获取问题 | 边界合法；非法形状 422；待澄清语义阻塞生成；硬上限不从目标推导；费用人数/晚数只展开一次 | 参数化 Pydantic/领域测试，UI 单位 |
| E22 子资源路径绑定 | A 有两个 Trip T1/T2 | 用 T1 路径读取/决定 T2 的 run/proposal/snapshot | 404且无副作用；同 owner 也须校验父子绑定 | API 参数化及 DB 对比 |

覆盖门槛：每个实现任务必须声明对应 E 编号；E01→03 是创建切片，E04→07 是 Mock 生成切片，E08→13 是确认修改切片。E16～22 为安全/恢复横向门槛，不能用 happy path 代替。路径尚未实现时应登记未通过，不能将设计表格记作测试通过。

测试部署独立库、独立 owner，不改旧 Checkpoint，不清理已有库。新增迁移只在适配任务中跑针对性持久化验证；本次纯文档阶段只检查契约引用、字段、版本/授权一致性及 Git diff，无完整数据库回归。
