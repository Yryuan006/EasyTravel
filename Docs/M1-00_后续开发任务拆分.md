## 2. 关键设计决策

1. 复用 PostgreSQL 正式事实模型；只追加需求收集、运行、上下文、决定/披露和 HTTP 幂等记录，不复制第二套草案/快照。
2. 未生成 Trip 可以存在；严格 TripRequirements 和非空 PlanDraftOutput 不被放宽来适配表单。
3. 所有价格及授权结论由服务端决定。Mock 不产生已核验价格，未知价格为 null；硬上限不由目标预算推导。
4. 需求版本与工作 revision 分开；新需求不重写旧稿，需求不一致时禁止旧确认。需求重规划统一 L3。
5. 采用正式保守分级；所有酒店改动 L3。整体确认不锁定所有项目，也不授权酒店变更，更不产生预订。
6. 一份历史确认绑定完整源修订、输入、notes 和披露。后续操作只有新草案，不覆盖快照。
7. 新 HTTP 幂等命令补齐创建/提案/决定等空白，原 apply/confirm 继续用 operation_receipts；批准必须一事务，不能拼接两次现有服务调用。
8. 不选新第三方研究服务、队列或模型依赖；LangGraph 已选型但不要求为 Mock 第一切片重建实验图。

## 3. 现有复用与未实现边界

复用正式 contracts/rules、Domain 候选与保护规则、Application/UoW/Repository、SQL 迁移器及不可变/FK/CAS/回执、M0 HTTP 错误包装与 health、Vue Shell/API 取消超时/过期响应模式、pytest/Vitest/Playwright 工程。逐模块证据见[业务状态与数据契约](M1-00_业务状态与数据契约.md)。不修改旧 Spike/M0-00，也不将其 demo 身份、schema、worker 或 Checkpoint 当正式产品组件。

本阶段没有实现上述任何新业务 API、表、页面、Mock 产品编排、登录、LLM、地图/酒店/交通数据源、预订支付、生产部署、RLS、多实例 Worker 或 READY 引擎。没有运行完整数据库测试或宣称 E01～22 已通过。
