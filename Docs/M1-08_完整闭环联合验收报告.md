## 完整用户生命周期

新测试 `frontend/e2e/zz-lifecycle.spec.ts` 的全部已提交业务写入由真实浏览器界面发起；没有使用 page.route、模拟响应、伪造候选或 SQL 修改业务事实。只用正式 GenerationWorker 在独立 Python 进程中受控执行一个任务；SQL 驱动只读采集证据。另有真实 API 反例请求验证缺预算、缺 L3 授权及 STALE 确认被拒绝。

1. A 在创建表单输入上海→杭州、2026-12-04～06、3 天、目标 2000 元、公共交通、酒店偏好及不爬山；人数与硬上限保持未回答，得到 Trip/i1，无工作稿。
2. 澄清人数为 2，得到 i2；缺硬上限的生成请求返回 409，无运行。再明确硬上限 2300 元，得到 i3。数据库保留 i1/i2/i3 和两条澄清回答，不把原文解析成用户事实。
3. 请求 INITIAL_PLAN，202 后由正式 Mock Worker 执行，SUCCEEDED 后从服务端重读 r1。每日、酒店、费用和风险可读；Mock 未标 VERIFIED，未知费用为 null。
4. 浏览器打开预算与风险预览、默认未勾选，明确勾选后确认 r1/S1；未新增酒店授权、预订或就绪事实。
5. 普通活动提案明确应用，得到 r2/UNCONFIRMED；S1 及原披露不变，无具体授权。
6. 酒店提案为 L3；缺授权的真实 API 请求被拒绝。浏览器审阅完整范围、明确勾选并应用，得到 r3，仅一条已消费酒店授权。
7. 另一份活动修改提案被明确拒绝，保持 r3，未新增工作修订或授权；拒绝决定持久化。
8. 编辑日期到 2026-12-11～13、硬上限到 3000 元及酒店偏好，得到 i4/STALE，仍为旧 r3。预览不可确认，直接确认旧稿 409；修复后的文案指向重规划。
9. 请求 REPLAN，成功只产生 v2 L3 提案；未批准时仍为 r3。浏览器审阅新旧需求、预算、未知费用和精确并集范围后明确批准，得到 r4、正式 requirements r2、context i4。
10. 重新读取风险与预算，重新勾选确认 r4/S2。查询历史 S1/r1 与 S2/r4，各自日期、需求、行程、预算和披露均与保存事实一致。
11. 再次明确应用普通修改，得到 r5/UNCONFIRMED，最近确认指针仍为 S2，S1/S2 均存在。
12. 终止并重启正式 local_server，PID 改变；刷新页面，凭证框为空，重新提供 A 凭证，读回相同 r5、S1/S2 和 REJECTED 提案。全部 21 张正式表的该 Trip 事实/迁移台账前后相同。最后切换 B，历史读取拒绝且 A 的数据清除，浏览器持久存储为空。

最终数据为 intake i4、WorkingDraft r5、requirements r2、2 份快照、2 条各消费一次的 L3 授权，明确体现三种版本计数及最近确认指针的区别。最终生命周期证据：`M1-08_完整生命周期HTTP与PostgreSQL证据.json`；全量运行原始证据另保留为 `M1-08_全量生命周期HTTP与PostgreSQL证据.json`。

## 安全与故障验证

正常演示以外，完整回归执行了非法输出/重复键/悬空费用/酒店漏字段、超预算、旧修订/旧风险摘要、精确授权缺项/多项/错误 hash、并发与同键换正文、COMMIT 失败、worker ACCEPTED/RUNNING/已提交窗口退出、显式 retry_of、跨 owner 与同 owner 错父 Trip、503 和错误脱敏等反例。详细测试节点和证据在矩阵中逐项列出。

`M1-08_全端点身份安全证据.json` 记录 66 个实际 FastAPI 请求/响应，并在前后对全部正式表比较行数与全行哈希。未提供 Token 为 401，跨 owner 为安全 404；伪 actor/owner 和客户端 candidate 直写为 422；错误响应仅含 code/message，不回显 Token、DSN、SQL 或堆栈。本地回环/Host/Origin 的 403、真实数据库不可达的 503 和静态 health 不替代业务就绪均随既有测试复验。

UI 故障测试使用路由中断/受控错误响应验证错误展示、保留原键和迟到响应抑制；这类注入明确不算作完整联通证据。正常生命周期不拦截或替换任何 API 响应。
