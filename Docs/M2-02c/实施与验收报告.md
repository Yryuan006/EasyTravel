## 严格契约

所有 DTO 继承已验收 PlaceContract：strict、frozen、extra=forbid。Application 会从序列化内容重建全部嵌套类型，拒绝 model_copy/model_construct 注入 VERIFIED 等值。字段长度和集合大小有界。

| 契约 | 关键语义 |
|---|---|
| TransitStopRef | ResourceRef 中内部站点 ID 与供应商 ID 分离；access_id 必填，角色只能 entrance/exit，无中心点角色或坐标推导 |
| TransitSegment | 明确内部线路、供应商线路 ID、方向、上车入口和下车出口；每段有独立 segment_id |
| ServiceOccurrence | 显式选定 occurrence_id，独立 fact_id/来源/日期/覆盖时段；本站到站、本站发车、下车站到达、本站首末班时刻；另有仅描述的线路首站发车时刻 |
| TransitFactScope / TransitSource | 明确服务日期、+08:00 有序覆盖区间、observed_at/expires_at、synthetic 引用及固定 SYNTHETIC_UNVERIFIED；不是实时承诺 |
| TimeAllowance | 步行秒数、政策缓冲秒数、已含两者的 required_seconds；已包含标记恒 true，已知 required 必须恰好为二者之和 |
| FirstBoardingAccess | 从明确活动资源/出口到首段上车入口，使用自身来源、适用范围及 allowance；不是模型分钟数 |
| TransferRule | 从前段下车出口到后段上车入口的有向政策，使用自身来源和范围，不默认同名站可互换 |
| TransitConnection | 前活动结束事件、已确定的有序一/两段和对应 occurrence_ids、首段政策与最多一次换乘政策；内部风险标记和请求范围 |
| F04FeasibilityCheck | 检查范围、连接/段/班次 ID、端点、目标日期、依赖 fact_ids、风险/严重性/动作、原因、就绪/本站到站/可行上车/发车/下车事件及规则版本 |
| F04ValidationReport | aware 注入时钟、规范化输入 SHA256、逐项结果、聚合与最短依赖 TTL；仅 F04，F03 NOT_EVALUATED；真实出行/确认快照/整体 READY 恒 false |

resolved_stops、已消歧线路、选定 occurrence_ids、活动出口及风险标记属于服务端可信内部输入，不提供外部自报身份或风险降级入口。本轮注册表是离线夹具注入的可信边界，未实现真实站点消歧服务。注册表中的同一内部站点不能绑定不同 ResourceRef；检查每一请求端点在注册表中精确存在。活动出口通过 FirstBoardingAccess 的完整资源与出口身份精确匹配。

不搜索班次、不排序选择最有利方案：用户已确定的每一 segment/occurrence_id 必须精确匹配，方向、供应商线路、站点、入口任一不符都不能借用其他服务。新模块不依赖 F03 类型、算法或报告。

## 确定性规则与完整性顺序

1. 请求仅支持同城、同日一/两段。请求时区不是 +08:00 为 FAIL。未注册端点为 FAIL。跨城、铁路/机场/实时范围或跨午夜请求返回 UNKNOWN；超过两段被严格 Schema 拒绝，不截断为两段。
2. 先按确切 segment + occurrence_id 绑定事实；空集合是 UNKNOWN / missing_service，绝非无服务。每项先检查 service_date、覆盖同日、观测是否在未来、是否过期（evaluated_at == expires_at 已过期）。任何候选不适用/过期，保留 UNKNOWN，不能从另一个来源提升。
3. 全部候选适用后比较完整结构化断言（不含来源元数据、fact_id、note），任何差异为 UNKNOWN / source_conflict；不能择优挑班次。不同日期和窗口也不能自动合并。同一服务多来源一致才继续。政策也遵循相同规则。
4. date_information_complete=false 时，不能根据负面状态或正常时刻推导 PASS/FAIL，返回 UNKNOWN。它表示覆盖范围内目标日期所需例外/运营资料完整，不代表真实核验。
5. 目标日明确 NO_SERVICE 或 SUSPENDED，在完整、未过期且无冲突时为 FAIL。本最小实现的负面事实必须覆盖完整目标日 `[00:00:00,23:59:59.999999]`；局部窗口不能外推全天停运，返回 UNKNOWN / fact_window_not_applicable。非运营状态不能同时填写乘车事件，避免矛盾负面载荷。停运状态为 UNKNOWN、服务状态 UNKNOWN，均保留 UNKNOWN。
6. 正常班次必须有本站到站、本站发车和下车站到达，且 `board_arrival <= board_departure < alight_arrival`。若提供线路首站 origin_departure，必须不晚于本站到站，但它不能补缺失的本站事件。不合法的事件顺序/时区视为不可靠事实 UNKNOWN；跨日 UNKNOWN；事件超出事实覆盖窗口 UNKNOWN。
7. 本站首班或末班字段缺失分别 UNKNOWN。完整有效的独立本站事件仍可用于判定明确赶不上；未知项不删除。首末班范围包含端点：`first_board_departure <= board_departure <= last_board_departure`；明确在范围外为 FAIL。首末班互相倒序为事实 UNKNOWN，不以矛盾数据宣告真实失败。
8. 首段就绪为 `previous_end + access.required_seconds`；换乘就绪为 `previous.alight_arrival + transfer.required_seconds`。就绪不晚于后段本站发车即 PASS，相等允许，晚一秒 FAIL。可行上车事件为 `max(ready_at, board_arrival)`，因此不会在车辆到站之前上车；报告展示该事件及来源中的到发事件。可在车辆到站后、发车前到站并上车。未提供独立计划上车时刻，本轮判断是否存在可行上车事件，不审查另一个行程版本的上车安排。
9. required_seconds 已含步行和政策缓冲，只加一次；不额外添加 F03 的 10 分钟/20% 缓冲。纯整数秒，无取整或模型估计。required_seconds 缺失为 UNKNOWN；已知合计与分量不相等拒绝输入。政策超出覆盖窗口或加完后跨日为 UNKNOWN。
10. 即使步行/换乘政策缺失，前活动结束或前车到达已经晚于后车发车，也有独立非负时长下界硬失败；保留相关未知政策项。某一服务未知不阻断其他独立服务及首段硬失败求值。

汇总沿用 FAIL > UNKNOWN > PASS > NOT_APPLICABLE；空连接范围不是 PASS。普通同城 UNKNOWN 为 warning；服务端风险标记 near_last_service、remote_only、mandatory、hard_constraint 将 UNKNOWN 提升为 blocker，铁路/机场标记也阻断为不支持。本轮额外自动保守识别距已知末班不超过 30 分钟的关键范围；仅提高风险，不覆盖服务端标记。30 分钟是规则版本内的内部风险阈值，不是实际运营承诺或实时保证。已知 FAIL 始终 blocker，模型文本无降级权限。
